# Speaker Vector 模型与短段补齐对比 — Claude Code 实验日志

- 分支 `dev/v0.6.9`，基线 HEAD `d1dd1c3c`；日期 2026-11-10（CST）。
- 接续 Doctor 日志第六批第 5 节「说话人短段（不足 3 s）没有声纹结果，另行跟踪」（[claude-code-doctor-zh.md](../2026-11-03/claude-code-doctor-zh.md)）。
- 本轮只评估 Speaker Vector，不涉及 Speaker Attribute、LID 和 turn-taking。仓库代码未改动；实验脚本、数据和原始结果都在会话临时目录（见第 8 节）。

## 结论

- **模型**：推荐 CAM++ 中英模型 `iic/speech_campplus_sv_zh_en_16k-common_advanced`。
  - 用自行导出的 ONNX，不用 sherpa-onnx 的现成产物，后者与原模型数值不一致（第 1 节）。
  - 在同一个严格阈值下，它的误关联率和拒识率都更低，速度快约 3 倍，内存约为基线的 1/5。
  - 它的优势来自跨语料、跨时长、加噪时分数尺度更一致，以及英文更好。在中文和中英双语对话数据内部，两者的区分力（EER）相当，跨语言也没有显出优势。
- **短段**：保留原长推理，不补齐。补到 2 s 或 3 s 在工作点上没有稳定收益，部分分组变差；0.5 s 段的计算量增加到 2～3.7 倍。

- **sherpa 产物的偏差**：CAM 层用 `avg_pool1d(ceil_mode=True)` 计算 100 帧的分段平均。
  - PyTorch 把最后一个不完整的段按实际帧数平均。
  - 导出后的 AveragePool（`ceil_mode=1, count_include_pad=1`）在 onnxruntime 1.23.1 里按 100 帧平均。
  - 因此只有第一层步长 2 之后的帧数恰好是 100 的倍数时，结果才一致。
- **本轮导出的做法**：把这一步改写为补零、按段求和、再除以各段的实际帧数。数学上与 PyTorch 相同，其余运算和权重不变。
- **sherpa 产物的实际影响**：它在本数据上的识别指标与忠实导出相近（按时长阈值下拒识率 22.5% 对 21.9%），偏差主要是保真问题。
- **固定长度要求**：两个候选都接受可变长输入，没有强制的输入处理。
- **其他候选，未纳入**：
  - WeSpeaker 的 VoxBlink2 SimAM-ResNet34：多语言，但模型许可为 CC BY-NC-SA 4.0，禁止商用。
  - WeSpeaker 的 VoxCeleb 系列：官方标注语言为 EN，没有可核实的多语言说明。
  - NeMo TitaNet：训练集为英文。

**有效语音与片段**
- 每段音频先过 Silero VAD：仓库的 runner，0.5/0.35 滞回。有效语音时长为有声的 32 ms 窗口之和；片段修剪到有声区间，两侧各留 3 个窗口。
- **注册**：每人每种语言 2 段完整片段，有效语音 3～10 s，取自一个 session 或 chapter。
- **测试**：同一人的其他 session 或 chapter，包括：
  - 完整段（3～15 s）；
  - 从第一个有声窗口起裁出的 0.5、1、2、3 s 有效语音；
  - ASCEND 的自然短应答（嗯、对、yeah、ok 等）。
  - 每个测试项另有一份加噪副本，信噪比 10 dB。

**排除规则**
- 内部含 ≥0.55 s 停顿的裁剪段（840 项）：路由的 VAD 会把它们切成两段。
- 同一录音的目标试验：LibriSpeech 中只有一个 chapter 的说话人（测试 11 人、校准 9 人），注册和测试来自同一录音，这类目标试验不计；这些人仍作为冒认者。
- AISHELL-1 每人只有一个 session：注册和测试是同一 session 的不同录音文件。

**划分**
- 说话人只属于校准集或测试集之一。同一片段及其裁剪只在一边。
- ASCEND 以对话为单位划分，同一场对话的录音不会同时进入两个集合。

**ASCEND 的清洗规则**（只依据元数据）
- 文件名里的说话人号或 session 号与字段不一致的行：排除。
- 分段录音（文件名带 `_1`/`_2`）：排除。
- 标注时间与对话另一方的语句重叠的片段：排除。

后两条规则和按对话划分，是我在预览测试结果时发现异常后加上的：ascend-14 的英文注册片段与本人测试的平均分和与冒认者的平均分几乎相同；四对对话的双方被分在了两个集合。规则对两个模型一视同仁，加上之后重新准备了数据、重新校准了阈值。ASCEND 没有性别标注，不参与同性别分析。

**规模**
- 共 32,995 项。
- 校准集：注册试验 37,698 次目标、915,192 次冒认；短应答对 740 / 2,418。
- 测试集：注册试验 36,834 次目标、873,654 次冒认；短应答对 278 / 1,184。

## 3. 方法

- **嵌入**：
  - 音频为 float32 [-1, 1]，先过仓库的 `FBank(80, mean_nor=True)`，再用 `SpeakerVectorRunner` 的会话选项推理，最后做 L2 归一化。
  - 对基线，这条路径与 `SpeakerVectorRunner.run` 的输出逐字节相同（12/12）。
  - 两个候选只差模型文件和图的输入名，用同一份原始音频。
- **试验**：
  - 注册试验：每段注册片段对比同一语料、同一集合中的全部测试项，同一说话人为目标试验。
  - 短应答对：说话人自己在不同 session 说的短应答为目标对；两个人说的同一个词为冒认对。
- **阈值**：只用校准集，每个模型各自校准。
  - **严格阈值**（主要工作点）：每个“语料 × 时长”格的误关联率都 ≤1%。
  - 另报告三种参照：只按时长分桶（每桶 ≤1%）、全部合并（=1%）、严格 0.1%。
- **指标**：在测试集上报告误关联率（FAR，附 Wilson 95% 上界和涉及的说话人对数）、拒识率（FRR）和 EER。
- **模型间差异**：对测试集的注册说话人做 1,000 次有放回抽样（bootstrap），给出 95% 区间。

**解读**
- **CAM++ 劣于基线的组**：
  - 冒认者是对话另一方（同一房间、同一段录音）：误关联率 0.97%，基线 0.01%。
  - AISHELL 整段：误关联率 0.25%，基线 0.00%。
  - 两者的区分力（EER）相同，差别来自工作点：ERes2NetV2 的严格阈值由英文决定，用在中文数据上偏严，代价是这些组的拒识率高得多。

## 5. 第二阶段：CAM++ 的短段补齐

- **补齐方式**：只补模型输入，波形长度不足目标时循环拼接后截取。按原始有效语音时长分桶。
- **阈值不变的原因**：严格阈值由不补齐的整段决定，三种方案都是 0.482。“原有阈值”与“重新校准”因此只在按时长分桶的阈值下有区别。

| 组（测试集） | 严格阈值 FRR：原长 / 补到 2 s / 补到 3 s | 按时长阈值（各自校准）FAR / FRR：原长 / 补到 2 s / 补到 3 s | EER：原长 / 补到 2 s / 补到 3 s |
|---|---|---|---|
| 0.5 s 裁剪 | 75.0% / 73.3% / 74.1% | 0.75%/34.0% / 0.71%/33.8% / 0.69%/34.3% | 10.71 / 9.99 / 10.15 |
| 1 s 裁剪 | 34.3% / 34.6% / 34.7% | 0.73%/14.7% / 0.67%/15.7% / 0.66%/15.6% | 5.79 / 5.94 / 5.85 |
| 2 s 裁剪 | 14.6% / 14.6% / 15.9% | 0.69%/7.3% / 0.69%/7.3% / 0.65%/8.1% | 3.99 / 3.99 / 4.26 |
| 自然短应答 <0.5 s | 98.9% / 97.8% / 97.3% | 0.22%/79.7% / 0.18%/79.0% / 0.16%/79.9% | 32.1 / 30.4 / 30.4 |
| 自然短应答 0.5～1 s | 83.5% / 86.4% / 85.2% | 1.14%/40.9% / 1.02%/45.5% / 1.25%/44.3% | 14.2 / 13.1 / 13.7 |

**说话人 bootstrap，补齐减原长**（按时长阈值、各自校准，百分点）
- 0.5 s：EER 补到 2 s −1.15～−0.18，补到 3 s −1.14～−0.06；FRR 区间都跨 0。
- 1 s：FRR 补到 2 s +0.61～+1.53，补到 3 s +0.53～+1.38。
- 2 s 补到 3 s：EER +0.01～+0.37，FRR +0.28～+1.33。
- 自然短应答 0.5～1 s：FRR 补到 2 s +1.67～+7.50。
- 沿用原长阈值时，补齐让 0.5 s 段的误关联率从 0.75% 升到 0.81%。

**成本**（预热后每次推理，含 FBank）

| 线程 | 0.5 s 原长 | 1 s 原长 | 补到 2 s | 补到 3 s |
|---|---|---|---|---|
| 4 | 7.2 ms | 9.7 ms | 14.5 ms | 20.3 ms |
| 1 | 8.8 ms | 14.0 ms | 23.3 ms | 32.8 ms |

**决定**：保留原长。补齐只在 0.5 s 段带来 EER 的小幅改善，在工作点上不转化为拒识率的收益，在 1 s、2 s 和 0.5～1 s 的应答上反而变差。

补齐后的输入仍只有原长的真实语音，不能算作更多证据。

## 7. 最小生产接入建议

本轮未实施，需另立批次。

1. **模型产物**：把导出脚本、`campplus_zh_en_advanced.onnx` 和一致性记录发布到 AlphaAvatar 的 HF 仓库，固定 revision。在 `model_files.py` 中加 `campplus` 条目；默认模型何时切换，另行决定。
2. **runner**：`SpeakerVectorRunner` 改为按会话的第一个输入名传入特征，不再写死 `feature`。FBank 不变。
3. **阈值**：
   - `SPEAKER_MATCH_THRESHOLD` 按新模型重新设定，本数据的严格工作点为 0.48。
   - 会话内跟踪的 `track_match_threshold`、`track_match_margin` 和 `segment_consistency_threshold` 需要单独做段对段的校准。
4. **已存储的声纹**：向量只能与同一模型的向量比较。存储时应记录模型标识；换模型后旧向量不参与检索，用户需要重新积累声纹。
5. **短段**：段结束时，如果从未满过一个 3 s 窗口，就在同一条窗口队列里对整段做一次原长推理，异步完成，不补齐，证据时长按原始有效语音记录。
   - 严格阈值下，1 s 和 0.5 s 裁剪段的误关联率不超过 0.04%，拒识率为 34%～75%。
   - 不足 0.5 s 的自然应答 EER 约 30%，不宜单独用来建立或延续跟踪。
6. **设备复测**：在目标设备上复测冷启动、内存和延迟。

## 结论

- **没有合格阈值**：
  - 按冻结协议（`protocol/v2.md`），单人探测模式选出 (一致性 0.40, 跟踪 0.55, margin 0, 身份 0.575)，它在校准、同池测试和独立测试上都满足 R1/R2。

- **限制工作点的机制**（不属于本批，单独列出）：
  1. 正常运行时，碎片轨迹和陌生人都会以生成的 user_id 存进库，成为后续检索的候选；一次误绑之后，会话结束的保存会用别人的声音覆盖已注册用户存储的声纹。

## 评估方法（供后续版本调整）

### 被评估的流程（与代码一致，`replay2.py` 头注释）

1. Router 的 Silero VAD（最短静音 0.55 s）切出语音段。Speaker 处理器按 3 s 窗口、1 s 步长推理：
   - 末尾不足一步的部分补一个尾窗；
   - 从未填满一个窗口的短段，按原长推理一次。
2. **一致性**：段内每个后续窗口与首窗口求余弦，任何一个低于 `segment_consistency_threshold`，整段作废，不归属任何人。
3. **轨迹**：段的首窗口向量与本来源的各条轨迹求余弦。
   - 最高分 ≥ `track_match_threshold` 时加入该轨迹；与次高分之差 ≤ margin（含同分）时记为未知；
   - 都不够时新建轨迹，每个来源最多 64 条，TTL 300 s；
   - 轨迹向量是创建它那一段的首窗口向量，之后不更新。
4. **身份**：每个已归属的段都用首窗口向量检索用户库，top-1 ≥ `SPEAKER_MATCH_THRESHOLD` 就把该段所属的参与者绑到这个用户。后面的段可以改绑。
5. **存储的声纹**：参与者缓存中的声纹向量从会话开始时的空值起，逐段合并（0.95 旧 / 0.05 新），所以基本由会话里的前几段决定。
   会话结束时，每个有用户的参与者都用它覆盖该用户存储的声纹（`merge_insert(user_id)`）；同一用户有多个参与者时，最后写入的生效。

### 会话构造（`harness2/solo.py`、`multi.py`）

- **单人会话**：开头 1 s 静音，之后 12 轮。每轮是一句原始录音（不超过 15 s），后接 2～6 s 静音，模拟 Avatar 的回答时间。
- **各层**：
  - S1：完整句子。
  - S2：从每句的起音点截取 0.6～2.0 s。起音点取第一个能量超过响度第 90 百分位十分之一的 32 ms 帧。
  - S3：ASCEND 中只说一种语言的会话。
  - S4：在 S1 上叠加 DEMAND 噪声，信噪比 10 dB 和 5 dB。噪声从三种环境中随机选一种，起点随机。
  - S5：远场录音。
- **两人会话**：12 轮交替，只用两人的探测录音，从不用注册录音。按轮间间隔分三类：
  - M1 交替：间隔 0.8～2.0 s，两人分属不同的 VAD 段；
  - M2 同段换人：间隔 0.05～0.35 s，VAD 不切分，两人在同一段里；
  - M3 真重叠：后一人在前一人结束前 0.3～1.5 s 开口。

  组合分两种：同户两名成员，以及一名成员加一名同语料、同切分的陌生人。
- **seed**：会话 `20261111`，两人会话 `20261112`，户 `20261111-<chain>`，正常运行 11，回放核对 7。

### 用户库（L0）与户（`households.py`）

- **L0**：注册会话在当时的代码默认值下跑真实链路，取会话结束时 Persona 为覆盖本人语音最多的那个参与者保存的声纹。
  - 前三个切分在第三批默认值下注册，独立测试 2 在本批默认值下注册。
  - 同一会话的一致性 0 向量用同一组参数回放，应得到同一声纹（余弦 ≥0.9999）。
- **户**：每户 5 人，分两种。
  - 随机户：成员按 seed 打乱后每 5 人一组。
  - 难户：只在同性别内组户（有性别标注的语料）。先取 ERes2NetV2 质心最相近的两人，再逐个加入与组内平均余弦最高的人。
- **探测对**：每户与同一 chain 中的会话组成探测对。
  - 成员的探测会话算"已注册"，探测录音来自注册以外的录音。
  - 非成员的全部会话（包括他们的注册会话）算"陌生人"。
  - 每个会话都从这户的 L0 开始，不保存。这就是协议说的"探测模式"。

### 计算方法（`replay2.py`、`eval2.py`）

- **只跑一次真实链路**：每个会话都以一致性 0 在真实链路上跑一次（`live2.py --consistency 0.0`），记录每段的全部窗口向量。
  这些向量与阈值无关，任何一组阈值都可以用 `replay2` 在这些向量上回放，不必重跑模型。回放与真实链路的一致性由 `verify2.py` 抽样核对。
- **指标**：
  - **会话误绑**：
    - 已注册：会话中任何一段在它自己的身份步骤之后，所属参与者绑在别人身上，就算一次；
    - 陌生人：任何一段已归属，且分数 ≥ 身份阈值。
  - **至少一次正确**：有本人语音的段里，至少一段绑到本人。
  - **按时长正确**：绑到本人的段里本人语音的秒数，除以本人语音总秒数。段内本人语音的秒数来自标注与 VAD 段的重叠。
  - **首次正确前语音**：会话开始到第一次绑对之间本人说话的秒数，另给对应的会话时间。
  - **未归属**：作废、同分或未知、无向量的段，按段数和按时长分别计。
  - **每会话轨迹数**：本人语音所在轨迹的条数。
  - **误合并**：不含标注语音的段被归入参与者的次数。单人会话里只有这一种形式。
- **区间**：
  - 计数比例用 Wilson 95% 区间；
  - 会话级比例另做按人整群的 bootstrap，1,000 次；
  - 风险估算 1−(1−p)^(N·K) 只作对照，不参与判定。其中 p 为陌生人对单个他人存储声纹的单次误识率，N = 5，K 为每会话检索次数。

### 选择规则与历史（`protocol/v2.md` 第 7、8 节）

- **网格**：
  - 身份 0.50～0.85，步长 0.025；
  - 跟踪 0.55～0.80，步长 0.025；
  - margin {0, 0.02, 0.04, 0.06, 0.08}；
  - 一致性 0.30～0.65，步长 0.05；
  - 共 6,600 个点，用校准切分计算。
- **判定规则**：
  - R1：已注册、陌生人分开算，全部层合并后的会话误绑 ≤1%，且每层 ≤2%；
  - R2：S1 至少一次正确 ≥90%，按时长正确 ≥70%；
  - 选择：满足两者的点中，取 S1 按时长正确率最高的。
- **第三批的结果**：
  - 满足 R1 的点 5,720 个，同时满足 R1、R2 的 611 个；
  - 单人选出 (0.30, 0.55, 0, 0.55)；
  - 多人调整：在每个参数 ±2 格内找仍满足 R1、R2 的点，共 54 个，取两人会话误绑最低的 (0.40, 0.55, 0, 0.575)，校准上 7/384。
- **第四批**：身份上调到 0.60，用独立测试 2 检验，见上文。
- **按网格重新选点**：`results/v2/grid-calibration.npz` 存有全部网格点的计数，用 `eval2.py select` 可直接重新选点。换规则不必重跑模型。

### 正常运行（`eval2.py sequential`）

- **会话序列**：每户取成员的探测会话（S1、S2、S3、S5；S4 是 S1 的噪声副本，不用），再从该 chain 中按 seed 抽 5 名陌生人，各取一个 S1 会话，一起打乱顺序。
- **保存**：从 L0 开始逐个会话运行，每个会话结束时按上面第 5 步保存。
  - 没有绑定的参与者存成新的生成用户；
  - 被绑定的参与者覆盖它所绑用户存储的声纹。
- **存储声纹的变化**：用存储的声纹与本人参考中心的余弦衡量。参考中心取本人全部探测会话中有本人语音的段的首窗口向量的平均值。

### 两人会话（`multi_eval.py`）

- **段的说话人**：取段内标注时长最多的人；本人占比 <80% 的段称为混合段，单独计数。
- **误绑**：段被绑到不是它说话人的用户；对陌生人来说，绑到任何用户都算。
- **其他指标**：
  - 他人语音随段归入：被绑定的段里，他人语音所占的比例；
  - 错加入：段加入的轨迹，其创建段的说话人与它自己的说话人不同。

### 回放核对（`verify2.py`）

- **抽样**：每个 chain 抽 4 户，每户取 4 个成员探测会话和 4 个陌生人会话。
- **准备**：把 L0 经 Persona VDB runner 的 save 写入 LanceDB。
- **运行与比较**：在真实链路上以被测参数运行（不加 override，即代码默认值），与回放逐段比较轨迹划分、检索结果和绑定后的用户。

### 复现顺序

1. 用 `harness/download*.sh` 和 `download4.py` 下载数据。
2. 用 `harness2/solo.py pool | independent | independent2` 构造单人会话。
3. 在真实链路上运行 `live2.py`：注册 chain 在代码默认值下运行；全部会话另以 `--consistency 0.0` 运行一遍。
4. 用 `households.py SPLIT [C TR M ID]` 生成 L0 和户。
5. 用 `multi.py SPLIT` 构造两人会话，再用 `live2.py --consistency 0.0` 运行。
6. 用 `eval2.py grid | select | detail | sequential` 和 `multi_eval.py [neighbourhood]` 算结果。
7. 用 `verify2.py seeds | compare` 核对回放。

每一步的具体命令和 shard 划分，见 `harness2/run_*.sh` 和本文件第三批记录的证据。

# 第五批：保存时把会话向量合并进用户存储的声纹

- 基线 `11e3a3c7`：用户已提交并推送第四批和轮次判断改名。本批改动未暂存、未提交。
- 用户的决定：
  - 运行中，会话向量与用户存储的声纹保持分开；
  - 会话结束保存时，如果参与者仍是识别到的那个用户，就按现有合并规则把载入的存储声纹和会话向量合并，再存回库里；
  - 本批只改说话人这一处。
- 载入的资料和它的状态由用户要求放进 Persona cache 里一个单独的对象（`_BaseProfile`），以后还可以在里面维护其他属性。

## 改之前的行为

- cache 有两份资料：
  - `_base_profile`：绑定用户后由 `load_profile()` 读入的库中资料，含用户存储的声纹；
  - `_observations`：本次会话的观测。
- 0.95/0.05 的合并只在观测那份上做，它从空开始，第一段直接取用。
- 保存时只写观测那份。LanceDB 用 `merge_insert("user_id")`，Qdrant 用同一点 ID 的 `upsert`，都会把原来存储的声纹整个替换掉。

## 保存规则

| 保存时的情况 | 写入库里的声纹 |
|---|---|
| 参与者仍是载入存储声纹时的那个身份，库里有存储的声纹 | 0.95 × 载入的存储声纹 + 0.05 × 会话向量，再归一化，与每段合并用的是同一个 `_merge_vector` 和 `SPEAKER_BETA` |
| 载入已完成，但库里没有存储的声纹 | 会话向量，与之前相同 |
| 本次会话新分配的用户（陌生人、碎片），载入完成与否都一样 | 会话向量，与之前相同 |
| 库里已有的用户，这个身份的载入没有完成（会话结束时仍在载入、被取消，或载入失败） | 不写说话人向量，库里存储的声纹不变；资料详情和运行状态照常保存 |
| 会话中改绑到另一个用户 | 改绑时清掉载入的资料；只和新用户载入的存储声纹合并，绝不会和改绑前那个用户存储的声纹合并；新用户的载入没完成就不写 |

- 一次会话最多把存储的声纹改动 5%。会话向量本身仍按每段 0.95/0.05 合并，一次 12 段的会话里第 1 段约占 57%。
- 会话结束前，Persona 会取消仍在进行的载入。所以如果绑定到库里已有的用户发生在会话结束前的瞬间，这次会话的声纹不会写入。旧代码在这种情况下会直接覆盖存储的声纹。
- 新分配的用户不在此列。真实链路第二次核对（`save5b`）时，有一个会话的最后一段刚建出新参与者，会话就结束了，它的载入被取消，结果这个新用户的声纹没有写入，而旧代码会写入。这是本批引入的回退。由于新分配的用户在库里不可能有存储的声纹，所以改为不必等载入，即上表第三行；第三次核对（`save5c`）通过。
