# AlphaAvatar v0.6.8 发布说明

[English](v0.6.8.md)

### 亮点

AlphaAvatar v0.6.8 完成了从由 LiveKit Agents 管理的应用到**由 AlphaAvatar 自己拥有的原生实时 Agent 运行时**的转变。应用启动、执行监督、模型／工具编排、已提交的轮次以及输出交付，现在都有明确的所有者。LiveKit 仍是首个实现的 RTC 传输，但它不再定义 Agent 生命周期或前台生成链路。

本版本还建立了**由处理器拥有的插件架构**。Persona、Memory 和 Router 围绕各自独立管理的处理器组织其能力，共享的 Foundation 运行时提供 Context、Loop、Provider 和 Voice 服务。具体的插件行为保留在其插件包中；Agents 包保留可复用的契约和运行时组合。

新的**原生流式模型与工具链路**取代了剩余的 SDK 执行路径。它支持结构化的模型输入与输出、增量的助手文本、函数调用、可配置的工具授权、规范记录发布、执行反馈，以及在模型选择提供时，于较长的工具操作之前给出的口头说明。

实时语音输出现在使用流式 PCM、有界的语音文本分段、异步的合成与播放，以及**按播放进度的转写文本同步**。语音仍是计时的权威：字幕交付跟随音频进度，不会卡住 PCM 播放。TTS 传输处理、重试上限、取消以及可选的首音频对冲，改进了对初始响应缓慢的处理，且不会悄然重放已经发出的音频。

最后，v0.6.8 统一了工作区和诊断布局，引入了紧凑的原生 Host CLI 和结构化日志，并将整个 Python 工作区升级到 **CPython 3.13**，配套一致的 Ruff、打包和 CI 检查。

### 新增内容

#### 原生 Host 与 RTC 所有权

* 引入 `avatar-host`，作为应用入口和生命周期协调者。
* 新增统一的 `alphaavatar` 命令，提供最基本的 `dev`、`start`、`--help` 和 `--version` 行为。
* 将 Host 职责拆分为应用引导、受管执行、进程监督、会话附着以及特定于后端的 dispatch。
* 将 LiveKit 媒体集成移到独立的 `avatar-rtc` 包。
* 实现由配置选择的 LiveKit 会话接入，包括按配置使用的原生 dispatch 和直接连接模式。
* 以原生的注册、分配处理、容量／准入决策、控制丢失处理和精确的执行收尾，取代 SDK 对 worker 和 job 生命周期的所有权。
* 会话附着拥有 RTC 连接和媒体适配器；它们不直接拥有共享推理服务，也不决定整个应用是否必须停止。
* 连接终止和执行终止有各自独立的边界。在当前配置的部署中，会话结束时仍可以结束其执行。
* 保留 `InferenceRuntime` 对其现有 runner 进程的所有权；Host 进程监督不会为这些 runner 创建第二个关闭所有者。
* 将通用生命周期和受取消保护的清理契约保留在 `avatar-core` 中，而不是在 Host 中重复实现。

架构上的分离是 v0.6.8 的交付内容。**不包括独立于连接的 Episode、持久的执行恢复、睡眠／唤醒调度和自主后台执行**；这些仍是之后路线图中的工作。

#### 由处理器拥有的 Persona 与 Memory

* 将 Persona 重组为独立管理的 **Profiler、Speaker 和 Face** 处理器。
* 将具体的 Persona 行为、处理配置、Provider、prompt 和特定于模型的逻辑移到 `avatar-plugins-persona`。
* 将面向 Agent 的 Persona 接口和共享数据契约与插件业务实现分开。
* 围绕由处理器拥有的能力重组 Memory，包括对话、工具、环境和检索行为。
* 重构 Memory 记录、owner 和上下文引用、note／导出投影以及本地存储边界。
* 区分持久的主 Memory 记录与派生的 Markdown 导出和索引。
* 保持 owner 与 scope 隔离，同时允许适当的、由 Avatar 拥有的 Memory 跨交互边界使用。
* 由有界的轮次消费者和规范记录消费者负责摄入已提交的输入和权威的模型／工具结果，而不是根据附带发生的 RTC 事件重建轮次。
* 处理器的启动、回滚和收尾保持在明确的生命周期所有权之下。

#### 运行时能力与已提交的轮次

* 将能力从 prompt 描述提升为类型化的、在运行时注册的定义和可调用绑定。
* 新增能力参数解析、别名／冲突校验和异步调用边界。
* 将 `AvatarModulePlugin` 注册与运行时拥有的插件实例及其生命周期分开。
* 新增已提交轮次事件流，下游消费者可以独立地响应权威轮次。
* 轮次捕获和不可变的感知 cutoff 保持由 AlphaAvatar 拥有。
* 分离规范输出记录、执行观测和面向用户的媒体交付；模型 Run 完成并不意味着客户端已经听到生成的语音。
* 在异步消费者之间保留精确的中断目标、输出标识和取消语义。

#### 原生的模型、Provider、Context 与工具执行

* 新增由 Foundation 拥有的 **Loop、Context、Provider 和 Voice** 组合。
* 前台模型和工具执行改由原生 Loop 负责，不再使用 `livekit.agents`。
* 为文本、媒体、函数调用、函数结果、流式增量和完成事件使用与 Provider 无关的模型输入／输出契约。
* 新增原生的 OpenAI Responses 流式实现，包括严格的事件顺序、推理续接处理和明确的协议错误。
* 继续通过 Provider 网关支持结构化后台任务，但不声称每个任务后端都支持前台流式。
* 对每次查询只捕获一次其 State 和固定的上下文前缀，在模型／工具的后续步骤中保持输入边界。
* 将特定于模型的 Provider 实现移到 `avatar-plugins-provider`，共享服务的所有权在 Foundation，各消费者专属的 prompt 由 Memory 和 Persona 保留。
* 新增运行时范围的工具可见性、参数校验、授权、可选审批、执行期限和如实的工具结果。
* 允许已获授权的能力无需强制的审批 UI 即可执行；被明确拒绝或需要审批的操作仍遵守其策略。
* 保留副作用和结果未知的语义：被中断的工具调用不会自动重放。
* 将 DeepResearch、RAG 和 MCP 接入原生的工具反馈链路。

#### 实时语音、说明与转写文本交付

* 在现有的 Router／Voice 边界内，VAD、STT、语音合成和转写文本同步保持各自独立管理。
* 保留 v0.6.7 的全双工打断和由 AlphaAvatar 拥有的轮次准入策略。
* 以流式 PCM 消费和有界队列，取代整句完成后才播放的 TTS。
* 改进增量语音分段：使用稳定的标点、词边界，以及针对数字、缩写和格式化文本的保护措施。
* 在快速的首个语音片段与之后更完整的片段之间取得平衡，并采用保守的预取和回答结尾处理。
* 由 `TranscriptSynchronizationProcessor` 继续负责按**本地音频播放进度**释放文本。
* 将字幕传输和反馈发布与音频帧交付循环解耦，因此缓慢的文本消费者不会拖慢 PCM 输出的节奏。
* 新增有界的启动／恢复音频储备，以及针对本地供给缺口的诊断；音频绝不会等到整个回答合成完毕才放出。
* 区分网络字节进度、PCM 帧组装、首音频期限、之后的读取超时、本地队列等待和有限的重试预算。
* 新增有界的重试行为，不会重新合成已经开始交付的语音。
* 新增可配置的首音频对冲，默认启用，在 **2.5 秒**后仍没有有效的首个音频帧时触发，受现有重试配额约束。它可能产生额外的合成费用；设置 `voice.tts.first_audio_hedge_after: null` 可将其禁用。
* 新增明确的语音交付失败结果和终止原因，以便把失败与正常完成或用户打断区分开。
* 只要音频输出处于活动状态，就选用自然、以口语为先的回答指引，而不在事后改写生成的回答。
* 新增指令，用于在合适的工具工作之前给出简洁的、**由模型生成且用户可见的说明**。说明使用正常的文本／语音输出链路，同时工具执行独立进行；它不是单独的模型请求，也不是私有的思维链。
* 默认不再为普通的模型等待强制加入通用的“思考中”播报；就绪状态和活动仍作为结构化状态信号提供。

基于播放的转写计时反映的是**本地 RTC 音频队列**，而不是经独立确认的浏览器扬声器播放位置。说明是可选的模型行为，并不保证每次工具调用都会有播报。

#### 三层插件工作区与模型初始化

* 将 `avatar-plugins` 重组为 **Foundation**、**Perception** 和 **Tools** 三个目录，不为公开的 Python 导入增加包名前缀。
* Foundation：Context、Loop、Provider 和 Voice。
* Perception：Character、Memory、Persona、Router 和 Status。
* Tools：DeepResearch、MCP 和 RAG。
* 将 Router 的 Addressing 和 Turn Taking 连同其配置和具体实现，移到由处理器拥有的目录中。
* 整合共享的 Foundation 服务，同时保留各消费者专属的处理器配置和生命周期。
* 移除单独的预下载注册路径。已启用的推理 runner 在初始化时解析缺失的模型文件。
* 从已校验的生效配置中选择推理 runner，而不是无条件加载所有可用模型。
* 统一模型缓存路径、加锁、离线行为，以及在有固定摘要值时的完整性检查。
* 当前的 Character／AIRI 集成保持可选，并**等待渲染器／RTC 验证**；它不作为经过完整验证的实时 Character 后端呈现。

#### 工作区、日志与诊断

* 统一以下内容的工作区路径：环境数据、用户、图、Memory 记录、episode／context 引用、会话产物、索引、日志和缓存。
* 将 Memory 主存储与 Markdown 导出投影和特定于后端的派生索引区分开。
* 新增原生的紧凑 Host 横幅，以及一致的时间戳、日志级别、源文件、进程 ID 和消息格式。
* 新增结构化的 Host JSONL 诊断，输出有界，并对敏感字段脱敏。
* 新增可选的开发者对话预览，覆盖已提交的用户输入、模型执行、工具调用和已接受的助手输出。
* 新增可选的 Core 事件／序号诊断，用于排查输入、Turn、输出和播放的顺序，而不把日志到达顺序当作全局事件序列。
* 在诊断术语中区分已生成、已记录、本地已发送、本地已播放以及失败／被打断的输出状态。
* 内容捕获保持可配置；Host JSONL 文件默认不包含新的对话正文预览。
* 保留 Host 和推理进程的取消安全清理，因此 Ctrl+C 可以完成所拥有资源的收尾，不再出现以前多进程 KeyboardInterrupt traceback 的情况。

#### Python 3.13、打包与质量

* 围绕 **CPython 3.13** 统一工作区元数据和支持的 Python 范围。
* 重组工作区及成员的 `pyproject.toml` 声明、可选依赖、包资源和隔离构建约束。
* 为所支持的 Python 版本更新 `uv.lock` 和开发工具。
* 统一 Ruff 0.12.9 设置、pre-commit 安全默认值、导入规则以及 `livekit.agents` 导入限制。
* 新增 Quality 工作流，检查 lock／元数据一致性、lint、格式、全部包的 wheel／sdist 构建、Twine 元数据检查、完整工作区安装、包导入、CLI 冒烟检查以及原生适配器生命周期契约。
* 根 CLI 和打包保持独立于 `avatar-app`，也独立于 Claude／Codex 或其他开发 Agent。

### 移除

* 从这条开发线中移除了当前使用的 `livekit.agents` AgentServer、JobContext、SDK worker／CLI，以及由 SDK 拥有的前台模型／会话生命周期。
* 从原生工作区安装中移除了 `livekit-agents` 和 LiveKit Agents OpenAI 插件依赖。
* 从当前运行时中移除了旧的外部消息桥接和频道启动依赖。原生 RTC 文本输入和外部工具集成仍然可用。
* 移除了以前的预下载函数工作流，改为在 runner 初始化时解析模型。
* 移除了原先基于 SDK 的组合所产生的过时包路径和重复的所有权路径。
* 没有为被替换的内部接口保留兼容别名；v0.6.8 有意一并更新这些契约。

### 迁移说明

**Python 与安装**

* 升级 Python 3.11 的检出时，使用 CPython **3.13**、当前的 `uv.lock` 和新的虚拟环境。
* 一并安装所需的工作区包和 extra；原生模型依赖可能需要特定平台的构建工具。
* 公开 CLI 属于 `avatar-host`：

```bash
ENV_FILE=.env.dev alphaavatar dev examples/agent_configs/mm/pipeline_openai_tools.yaml
# or
ENV_FILE=.env.dev alphaavatar start examples/agent_configs/mm/pipeline_openai_tools.yaml
```

**配置与运行时所有权**

* 保留现有的顶层 Avatar、Runtime、Voice、Router、Memory、Persona、Tools 及其他部分。Host 设置从其自己的 `host` 子树读取。
* 已实现的 RTC 后端使用 `host.rtc.backend: livekit`。其他 RTC 后端仍是未来的工作。
* LiveKit 的分配／dispatch 标识不是模型的 `run_id`、Episode 或操作系统进程 ID。
* 不要把连接分离理解为持久的 Episode 执行；本版本不提供在断开连接后长期存在的执行。
* 插件和模型缓存目录遵循新的工作区／包布局。迁移后请更新相对于仓库路径的启动脚本或部署挂载。

**TTS 与诊断控制**

* 语音输出链路使用流式 PCM 和按播放进度的字幕；它不提供单独的默认“文本先于语音”交付模式。
* `voice.tts.first_audio_hedge_after` 默认为 `2.5` 秒。将其显式设为 `null` 可禁用推测性的备用请求。对冲使用现有的重试配额，可能增加外部 API 费用。
* 对话预览日志可能在开发控制台中暴露用户提供的内容。诊断文件的内容捕获需要单独选择开启，外部终端／容器日志需要另行考虑。
* 最基本的 `dev`／`start` CLI 是本版本的一部分；安装器、Doctor、配置 profile／bundle、引导式凭据设置和 App 入门引导计划在之后的版本中提供。

当前用法和职责见 [Host](../../avatar-host/README.md)、[插件布局](../../avatar-plugins/README.md)、[工作区](../layouts/avatar-workspace.md)、[模型缓存](../layouts/models-cache.md)和[开发环境](../../CONTRIBUTING.md)。

### 验证

开发分支的 Quality 工作流验证 lock 是否最新、工作区检查、Ruff lint／格式、wheel／sdist 元数据、完整的 CPython 3.13 工作区安装、已移除的 Agents SDK 包确实不存在、包导入、最基本的公开 CLI 命令以及适配器生命周期契约。

原生 LiveKit 交互已经通过模型／工具请求、音频输出、同步的转写文本和有序的执行收尾进行过实际运行。Provider 计时、远程网络性能和设备播放仍取决于部署。最新的首音频对冲和自适应说明行为必须针对真实的 Provider 流量和客户端渲染进行评估；仅凭构建成功无法确立这些用户体验结果。

该工作流不能代替全面的实时 RTC、多参与者、长时间运行、压力或平台安装测试。这些更广泛的检查以及面向开发者的诊断另行安排。

### 说明

* **LiveKit 是 RTC 后端，不是 Agent 运行时。** 本版本实现了 LiveKit；不声称支持所有 RTC 提供方。
* `HostExecution` 表示一个受管的 Avatar 执行实例，而不是单次模型 Run 或持久的 Episode。
* 已提交的轮次和规范记录保留了输入权威、模型完成、工具结果和最终本地输出交付之间的区别。
* Character 呈现仍是可选的；在渲染器和传输链路完成端到端验证之前，`Pending` 是正确的状态。
* 内部契约继续优先保证一致的架构演进，而不是向后兼容。
* 本版本不引入持久的 Context 恢复、自主后台 Episode、睡眠／唤醒、Dream、Reflection、跨设备的应用打包以及可配置的 runner 并行。

### 架构方向

v0.6.8 填补了 v0.6.7 留下的应用与运行时所有权缺口：

```text
alphaavatar dev / start
           |
           v
      AvatarHost
       |       \
       |        +-- Application services / health / shared inference
       |        +-- Process supervisor / HostExecution management
       |        +-- Session manager / RTC backend selection
       |                         |
       |                         v
       |                    LiveKit transport
       v
    AvatarEngine
       |
       +-- Core Perception / committed Turn / Output Runtime
       +-- Foundation: Context / Loop / Provider / Voice
       +-- Perception: Router / Memory / Persona / Status
       +-- Tools: DeepResearch / RAG / MCP
       |
       v
 Native model + tool execution
       |
       +-- Canonical output records and execution signals
       +-- Incremental assistant text / optional commentary
       +-- Router speech synthesis and transcript synchronization
       |
       v
 RTC media / captions / status delivery
```

**下一步：** v0.6.9 侧重于安装／配置体验、Doctor 与指标、可配置的 runner 并发，以及系统性的实时压力／缺陷测试。之后的版本引入 App 体验、更强的身份／引用契约、高级检索，最终实现独立于连接的持久执行生命周期。
