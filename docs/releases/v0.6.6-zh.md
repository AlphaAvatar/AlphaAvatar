# AlphaAvatar v0.6.6 发布说明

### 亮点

AlphaAvatar v0.6.6 着重于**通过更强的时间一致性、保留更久的实时感知、更清晰的运行时能力感知和更整洁的会话组织来改善用户体验**。

本版本把共享感知架构扩展为统一的**时间对齐多模态运行时**。视频、音频、语音、转写、用户直接输入以及媒体来源的生命周期事件现在共用同一个运行时时钟，并可冻结为不可变的感知快照，快照带有明确的起始和结束来源状态。

Avatar 模型管线也围绕与供应商无关的 `ModelInput` 重构。时间对齐、视觉选择、prompt 渲染和 Provider 转换现在职责清晰分离。当前的多模态输入渲染为结构化的时间线，不再注入缺乏时间上下文、彼此无关的帧。

ENV Memory 现在同时消费**连续的环境音频和视觉感知**，在同一时间线上对齐二者，并在语音仍在进行时自适应地推迟周期性的记忆边界。

v0.6.6 还新增**运行时能力感知**。记忆、用户画像、说话人识别和人脸识别等内部能力现在可以通过框架级的能力元数据描述自身。已启用的能力注入 Avatar 的 system prompt，使模型了解当前运行时能做什么，而不必把内部组件暴露为可调用的工具。

感知数据的保留也从固定的记录条数转向**根据实际生产节奏计算的按时间容量**。视频发布间隔和音频帧大小现在同时作为实时输入和缓冲区容量的唯一依据，即使采样配置变化，保留量也可预测。

最后，会话和时间处理得到大幅整理。运行时同步时间、应用墙钟时间和面向参与者的时间现在明确分开，会话数据则按创建日期分组，便于浏览和维护。

### 新增内容

* 新增共享的运行时时间模型：

  * 新增 `RuntimeClock`、`RuntimeTime` 和 `RuntimeTimeRange`，作为感知与输出共用的时间基础。
  * 运行时的排序、时长、截止点和时间对齐使用单调时间，而不是面向用户的时间戳。
  * 观测保留明确的时间范围，而不只依赖到达顺序。
  * 感知来源的状态转换与媒体观测使用同一个运行时时钟。
  * 运行时截止点可以原子地冻结一个不可变的感知边界。
  * 保留起始和结束来源状态，使下游消费者能够区分历史证据和当前可用的媒体。

* 分离运行时、应用和面向参与者的时间语义：

  * 实时同步仍由 `avatar-core` 通过 `RuntimeClock` 和单调时间戳负责。
  * 应用墙钟时间用于会话创建、持久化时间戳和文件系统组织。
  * 面向参与者的时间在可用时使用明确的用户或浏览器时区信息。
  * 同一会话中的多个参与者可以各自维护独立的时区上下文。
  * 运行时上下文现在支持按参与者区分的当前时间快照，不再假设整个会话只有一个时区。
  * Persona 的登录和画像更新时间戳以结构化的 datetime 存储，只在构建面向模型的上下文时才渲染为相应用户的时区。
  * Memory 和 Persona 的持久化不再依赖 prompt 中人类可读的时间戳来排序或存储。

* 新增统一的感知事件和媒体来源生命周期跟踪：

  * 新增会话级的有序 `PerceptionEvent` 流。
  * 新增明确的摄像头、屏幕和麦克风生命周期事件。
  * 来源世代可防止过期的轨道读取方关闭或修改更新的媒体来源。
  * 感知快照暴露遗漏的事件数和保留缺口。
  * 下游消费者可以显式检测不连续之处，而不是默默假设时间线完整。

* 感知契约的 schema 化和枚举化：

  * 流种类、观测种类、事件种类和媒体来源种类现在使用明确的运行时枚举，而不是分散的字符串字面量。
  * 感知事件 schema 与运行时实现分离。
  * 观测到流的路由现在使用类型化的 `ObservationKind` 和 `PerceptionStreamKind` 契约。
  * 更严格的 schema 边界减少了意外的跨流错配，并为感知 API 的未来外部集成做好准备。

* 新增与供应商无关的时间对齐：

  * 新增 `PerceptionTemporalAligner`，用于共享的多模态对齐。
  * 新增固定和以语音为锚点的对齐模式。
  * 连续的观测可以跨越多个相互重叠的时间切片。
  * VAD 语音片段和最终转写文本可以按来源和片段 ID 配对。
  * 保留语音停顿和非语音间隙，但不会把每个语音片段变成单独的用户轮次。
  * 直接输入的文本和上传的媒体仍作为轮次结束时的输入，不会被分配到更早的时间切片。
  * 同一个对齐器可被 Avatar、ENV Memory 和未来的感知消费者复用。

* 新增不可变的轮次快照：

  * `TurnRuntime` 冻结与每次用户输入关联的感知状态。
  * 语音轮次和直接文本输入现在共用同一个轮次级感知契约。
  * 重试和工具后续的模型调用复用原来的轮次快照，而不是观察之后的感知状态。
  * 直接文本和上传的输入与轮次截止点一起原子提交。

* 重构多模态视觉处理：

  * 移除旧的有状态 Sampled Frame Vision 运行时模型。
  * 视觉选择现在是作用于已对齐感知的纯操作。
  * `VisualFrameSelector` 不再管理感知游标、来源状态、后台任务或本地帧缓冲区。
  * 实时模式对每个时间切片独立采样。
  * VLM 模式先保证语音切片和间隙切片的语义覆盖，再分配额外的帧预算。
  * 视觉选择从不推断摄像头或屏幕当前是否活动；权威的来源状态来自时间对齐。

* 新增与供应商无关的模型输入与 prompt 管线：

  * 新增 AlphaAvatar 自有的模型输入消息，以及文本、图像、音频、时间、函数调用和函数输出部分。
  * prompt 渲染按模型输入类型选择，而不是按模型供应商选择。
  * prompt 代码不再依赖供应商专有的消息结构。
  * Provider 适配器负责最终转换为 SDK 专有的请求格式。

* 新增结构化的当前输入渲染：

  * 当前的多模态轮次渲染为结构化的 `alphaavatar_input` 时间线。
  * 语音片段、停顿、视觉证据、来源状态转换、感知缺口和直接输入保留各自的相对时间位置。
  * 输入结束时的媒体状态被明确表示为当前摄像头和屏幕可用性的权威依据。
  * 较早的视觉帧仍可作为历史证据使用，不会被误认为当前的实时画面。
  * 一个轮次内的多个语音片段仍是一条用户消息，不会变成多个对话轮次。

* 改进运行时上下文注入：

  * 动态记忆、参与者时间、计划、反思和临时行为规则与用户的实际输入保持分离。
  * 运行时上下文只作用于当前这次模型调用。
  * 稳定的 persona 和行为指令保留在 system prompt 中，以提高 prompt 前缀的稳定性。
  * 参与者时间上下文可以表示同一会话中处于不同时区的多个用户。
  * 历史媒体在模型调用前被压缩，并明确标注为属于较早的消息。

* 新增内部运行时能力描述：

  * 新增框架级的 `AvatarCapability` 元数据和类型化的能力名称。
  * 内部能力可以通过 `@avatar_capability` 直接声明在其抽象运行时组件上。
  * 能力元数据由具体的插件实现继承，插件开发者因此可以专注于实现运行时契约，无需重复编写能力描述。
  * Persona 目前提供画像、说话人识别和人脸识别能力。
  * Memory 提供对话、环境、工具和图记忆能力。
  * 已启用的内部能力注入 Avatar 的 system prompt。
  * 内部能力与可调用工具明确区分，也不表示所需的实时证据当前可用。
  * 能力模型的设计支持未来把 Memory 拆分为独立注册的子能力。

* 新增供应商专有的多模态输入适配器：

  * AlphaAvatar 插件和 agent 基于与供应商无关的时间输入工作。
  * 媒体编码、Base64 转换、WAV 构造和 SDK 专有的消息转换属于 Provider 适配器。
  * 连续的环境音频可以转换为完整的面向模型的音轨，同时保留 AlphaAvatar 的时间元数据。
  * 未来的原生多模态供应商可以用各自的音频、视频和时间戳表示来消费同样的已对齐输入。
  * 供应商专有的输入行为不再渗入 ENV Memory 或 Avatar 的 prompt 逻辑。

* 新增音视频 ENV Memory：

  * ENV Memory 现在同时消费视觉感知和连续的麦克风音频。
  * 环境音频使用原始的 `AUDIO_FRAME` / `AUDIO_SEGMENT` 观测，而不是经 VAD 选出的语音。
  * 背景人声、音乐、环境声及其他麦克风证据都可以用于环境记忆。
  * 语音帧、语音片段、转写文本、键入的文本和用户上传的媒体不计入 ENV 证据。
  * 视觉帧按 ENV Memory 策略采样，音频则保持连续。
  * ENV Memory 使用与运行时其余部分相同的固定时间对齐基础设施。
  * 来源状态转换以及起始／结束时的媒体状态作为环境证据保留。

* 新增自适应的 ENV Memory 调度：

  * 周期性的 ENV Memory 更新和用户轮次触发的更新共用一个调度器。
  * 周期性的记忆边界不再立即切断正在进行的语音片段。
  * 到达正常的间隔边界时如果语音仍在进行，ENV Memory 会异步等待当前片段结束。
  * 提取开始之前，由此得到的感知截止点冻结在完整的语音边界上。
  * VAD 只用作调度边界信号；ENV Memory 仍处理原始的连续环境音频。
  * 可配置的最长推迟时长可防止连续讲话、会议、电视或其他长时间持续的音频无限期地阻塞记忆更新。
  * 达到最长推迟时长时，在语音中途强制设置的边界会被明确记录。
  * 会话关闭仍是硬边界，会排空待处理的 ENV 工作，不等待语音结束。

* 重构感知流的保留：

  * `PerceptionStream` 现在是通用的有界序列缓冲区，不再自行决定各模态专属的缓冲区大小。
  * 流容量由 `PerceptionRuntime` 显式提供。
  * 高频视频和音频的保留量根据配置的时间保留跨度和实际生产节奏计算。
  * 视频发布间隔和音频帧大小现在作为共享配置，同时决定 RTC 输入行为和感知缓冲区大小。
  * 改变视频采样频率或音频帧时长会自动调整所需的流容量。
  * 这让短时回放容量在时间上大致保持一致，而不是取决于任意设定的条目数。
  * 对不存在单一稳定生产速率的文本流和汇总事件流，仍各自独立设定上限。
  * 感知流仍是短时的实时缓冲区，而不是长期的记忆存储。

* 改进感知缺口处理：

  * 高频观测可以继续供专门的消费者使用，而不必进入长期的标注时间线。
  * 事件保留缺口会暴露遗漏数量，而不是假装不可用的事件从未发生。
  * 即使中间的事件历史不完整，起始和结束的来源快照仍具有权威性。
  * 消费者滞后和保留边界在流契约层面保持明确。

* 新增与传输无关的 `OutputRuntime`：

  * 新增共享的输出流和时间对齐的输出时间线。
  * 新增 Assistant、临时、状态和角色输出 lane。
  * 新增明确的输出、轮次和分块标识。
  * 新增与传输无关的打断和完成控制。
  * 生成的源文本、音频、播放反馈、对齐和已交付的转写文本分别表示。
  * 被打断的输出保留已经交付的证据，同时拒绝迟到或未播放的输出。

* 更新状态和临时语音处理：

  * 机器可读的状态与可选的、用户可见的临时语音分离。
  * Status 插件不再直接负责传输层的语音输出。
  * 临时语音经由 AlphaAvatar 输出和 Router 路径运行。
  * 新的 Assistant 输出可以立即打断正在进行的临时语音。
  * 延迟的填充语音不再在 Assistant 的最终回答之后播放。

* 新增感知播放进度的转写文本同步：

  * 生成的文本和实际交付的转写文本分别跟踪。
  * TTS 输出发布文本到音频的对齐信息。
  * 传输适配器发布播放进度。
  * 可见的临时转写文本跟随音频的实际交付。
  * 打断之后，不会发布从未播放过的文本。
  * 取消之后，已交付的转写文本仍然可用。

* 把 Interaction Router 扩展到输出处理：

  * 输入路由继续管理音频活动和转写。
  * 输出路由现在包括语音合成和转写文本同步。
  * TTS 能力仍由 Voice 插件负责，路由和取消则由 Router 负责。
  * 长期存在的合成任务在同一逻辑输出的多个文本分块之间保持顺序。

* 新增分阶段并发的运行时生命周期管理：

  * 运行时插件按依赖安全的阶段启动和停止。
  * 同一阶段内的独立插件并发执行。
  * 启动回滚和尽力而为的关闭改进了故障处理。
  * RTC 输入只在感知消费者和 Router 处理器就绪后才启动。
  * 关闭时先停止生产者，再停止下游消费者。

* 改进会话和参与者的组织：

  * 会话现在按应用本地时间的创建日期分组：

    ```text
    sessions/
    ├── 2026-08-16/
    │   ├── <session_id>/
    │   └── ...
    └── 2026-08-17/
        └── <session_id>/
    ```

  * 会话创建时间只记录一次，即使会话跨过午夜也保持不变。

  * 会话的文件系统路径不再根据参与者／浏览器的时区元数据推算日期。

  * 参与者的传输身份与逻辑用户身份分离。

  * 一个会话可以表示同一房间内的多个参与者，参与者 ID 不再从人类可读的时间戳派生。

  * Persona 身份解析会更新 `resolved_user_id`，同时保留原来的参与者／用户身份和运行时对象引用。

* 改进 Memory 和 Persona 的时间戳语义：

  * 记忆条目现在使用结构化的创建时间戳，而不是会话开始时面向用户的时间字符串。
  * 记忆的排序和去重直接基于结构化的 datetime 进行。
  * Memory VDB 元数据使用明确的 `created_at` 字段，取代缩写的 `ts` 字段。
  * Persona 画像字段使用结构化的 `updated_at` 时间戳。
  * 画像更新时间在实际发生基于人脸、说话人或对话的画像变更时生成。
  * Persona VDB 元数据使用明确的 `updated_at` 字段。
  * 只有在为模型渲染 Persona 或运行时上下文时，才进行人类可读的时区转换。
  * 这可防止存储时间戳与某个参与者的时区或 prompt 表示耦合。

* 继续清理 LiveKit 边界：

  * LiveKit 的音频、视频、状态、转写文本和临时音频转换都位于 LiveKit 入口边界之内。
  * AlphaAvatar 的运行时、prompt、感知、ENV Memory、Router 和输出逻辑越来越多地基于 AlphaAvatar 自有的结构工作。
  * RTC 生产者配置通过入口注入，不再把传输专有的常量泄漏到 Core 感知中。
  * LiveKit 仍是默认的 RTC 后端，同时更多 AlphaAvatar 自有的运行时行为被移出 `livekit.agents`。

### 验证

集成后的 v0.6.6 运行时已在更新后的感知、模型输入、Memory、Persona、ENV Memory、会话和输出路径上测试，包括：

* 多模态时间对齐；
* 摄像头和屏幕的生命周期转换；
* 历史与当前视觉状态的区分处理；
* 直接文本和语音的轮次快照；
* 一个轮次内的多个语音片段；
* 结构化的多模态 prompt 渲染；
* 与供应商无关的模型输入转换；
* 基于连续音频和视觉的 ENV Memory 提取；
* 语音进行期间的周期性 ENV Memory 更新；
* 自适应的语音边界推迟和最长推迟兜底；
* Memory 和 Persona 内部能力的注入；
* 跨不同时区、按参与者区分的当前时间渲染；
* Memory 和 Persona 结构化时间戳的持久化与重建；
* 按时间计算的视频和音频感知缓冲区大小；
* 在按日期分区的文件系统路径下创建会话；
* 临时语音打断；
* 与播放同步的转写文本交付；
* 分阶段的插件启动和关闭。

### 说明

* 在 v0.6.6 中，LiveKit 仍是默认的 RTC 传输。
* LiveKit `AgentSession` 仍负责 Assistant 最终交付和轮次生命周期的部分工作，AlphaAvatar 自有的运行时边界则在持续扩展。
* Assistant 最终输出归属的迁移有意保留为未完成状态，将在后续版本中继续。
* AlphaAvatar 继续运行自己的 Router VAD 和 STT 路径，轮次处理仍保留临时的 LiveKit 兼容路径。
* ENV Memory 收听连续的麦克风音频。VAD 语音信息只用于选择更合适的记忆提交边界。
* 当进行中的语音超过配置的最长推迟时长时，ENV Memory 会强制设置周期性边界，避免记忆延迟无限增长。
* 感知流的保留是为有界的实时回放和容忍消费者滞后而设计的，不用于长期媒体存储。
* 能力可用并不表示所需的摄像头、麦克风、语音或其他实时证据当前存在。
* 面向参与者的时区上下文与应用的持久化时间戳和实时单调计时保持分离。
* 面向模型的历史视觉和音频载荷会被压缩，使较早的媒体不会被误认为当前感知。
* 供应商专有的媒体转换属于 Provider 边界。Core 运行时和插件基于 AlphaAvatar 自有的多模态表示工作。
* 内部 API 继续优先考虑架构的快速迭代，而不是向后兼容。

### 内部方向

v0.6.6 让 AlphaAvatar 从相互独立的共享感知流走向统一的时间对齐多模态运行时：

```text
RTC / Device Adapters
        ↓
EnvObservation + Source State
        ↓
PerceptionRuntime
  ├── audio
  ├── speech
  ├── video
  ├── screen
  ├── text
  └── ordered events
        ↓
RuntimeTime + PerceptionCutoff
        ↓
PerceptionTemporalAligner
        ↓
AlignedPerception
   ┌───────────────┴────────────────┐
   ↓                                ↓
Avatar                            ENV Memory
   ↓                                ↓
VisualFrameSelector           ENV evidence selection
   ↓                                ↓
Context / Prompt Pipeline     Provider-neutral temporal input
   ↓                                ↓
ModelInput                        ProviderGateway
   └───────────────┬────────────────┘
                   ↓
             Provider Adapter
                   ↓
        Gemini / future Omni models
```

内部运行时能力现在走一条并行的元数据路径：

```text
Memory / Persona abstract capabilities
        ↓
@avatar_capability
        ↓
AvatarCapability metadata
        ↓
Active runtime composition
        ↓
Avatar system prompt
        ↓
Model capability awareness
```

感知数据的保留量现在根据时间语义计算，而不是任意设定的记录条数：

```text
Configured producer cadence
  ├── video publish interval
  └── audio frame duration
        +
Retention horizon
        +
Safety headroom
        ↓
Derived stream capacity
        ↓
PerceptionStream
```

时间职责也已明确分开：

```text
RuntimeClock / RuntimeTime
        ↓
Realtime ordering, duration and alignment

Application Wall Clock
        ↓
Session creation, persistence and filesystem dates

Participant Time Context
        ↓
User timezone and current human-facing time
        ↓
Participant-scoped runtime context
```

输出侧走一条并行的、AlphaAvatar 自有的路径：

```text
Source Text / Status / Character Output
        ↓
OutputRuntime
        ↓
Interaction Router
  ├── Speech Synthesis
  └── Transcript Synchronization
        ↓
Transport Output Adapter
        ↓
Audio Playback + Playback Feedback
        ↓
Delivered Transcript
```

架构职责越来越明确：

* `avatar-core` 负责与传输无关的感知、输出、实时计时、来源状态、保留、截止点和对齐语义。
* 应用运行时负责会话生命周期、应用墙钟时间、参与者身份和文件系统组织。
* Interaction Router 负责实时输入／输出路由和取消决策。
* Voice 插件负责 VAD、STT 和 TTS 能力。
* Avatar 负责轮次解读、视觉选择、上下文组合、prompt 渲染和模型编排。
* Persona 负责持久的用户画像、与身份相关的感知和用户级运行时状态。
* Memory 负责持久的对话、工具、图和环境记忆行为。
* ENV Memory 负责环境证据策略和持久的环境记忆提取。
* Provider 适配器负责模型和 SDK 专有的多模态转换。
* 入口负责 RTC 和外部传输的转换。
* 内部运行时能力由框架契约声明，而不是由传输或供应商实现声明。
* `AvatarEngine` 继续收缩，逐步只负责组合和高层编排。

v0.6.6 建立了时间、能力、持久化和与供应商无关的边界，这些边界是未来的原生实时多模态模型、更丰富的多用户会话、更深入的 ENV 理解、模块化的 Memory 能力，以及继续从 AlphaAvatar 自有运行时行为中移除 `livekit.agents` 所必需的。
