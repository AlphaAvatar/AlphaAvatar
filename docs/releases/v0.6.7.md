# AlphaAvatar v0.6.7 Release Notes

> Draft — semantic addressing, conversation focus, and the visual-only proactive-turn interface remain to be completed before the final v0.6.7 release.

### Highlights

AlphaAvatar v0.6.7 introduces an **AlphaAvatar-owned multimodal turn-taking runtime** and removes LiveKit's text-based turn detection from the active interaction path.

Turn decisions are no longer inferred indirectly from LiveKit transcription callbacks. Speech activity, completed speech segments, transcripts, visual observations, addressing evidence, endpoint assessments, and final turn decisions now flow through AlphaAvatar-owned runtime contracts.

This release promotes environment annotations into first-class ordered **Perception Events**. Face detections, invocation detections, interaction targets, and final turn-taking decisions can be independently published, consumed, replayed, and attached to the observations that produced them.

Perception identity and lineage have also been normalized. Sources, source generations, semantic segments, transport participants, and perceived entities now use typed references instead of loosely coordinated metadata strings. Speech and transcript observations share the same `PerceptionSegmentRef`, while derived observations retain their own producer source identity.

The new Turn-Taking Processor builds revisioned, immutable evidence snapshots and separates model assessment from deterministic routing policy. A local Smart Turn endpoint model evaluates whether the current speech candidate is complete, while independent addressing evidence determines whether the speaker is addressing the Avatar, another participant, a group, or an unknown target.

Audio-only and audio-visual modes now follow different policies. Audio-only interaction can treat speech as Avatar-directed by channel semantics. Audio-visual interaction requires addressing evidence before committing or interrupting, preventing unrelated background speech from automatically triggering the Avatar.

v0.6.7 also introduces an annotation-driven `AvatarTurnController`. Final `COMMIT` and `INTERRUPT` decisions are consumed as Perception Events, frozen into exact turn snapshots at the decision-event sequence, and submitted explicitly to the Avatar response path.

The result is a lower-coupled, full-duplex architecture in which:

* VAD determines speech activity;

* STT determines what was said;

* Smart Turn determines whether the current turn is complete;

* addressing processors determine who is being addressed;

* Router policy decides whether to hold, commit, remain passive, interrupt, or cancel;

* Avatar owns the final user-turn snapshot and response trigger.

### What's New

* Promoted environment annotations into first-class Perception Events:

  * `EnvAnnotation` now uses typed `AnnotationKind` values.

  * Annotation publication creates ordered session-level Perception Events.

  * Annotation consumers maintain independent cursors and can explicitly detect retention gaps.

  * Annotation events can trigger downstream processors without direct callbacks between plugins.

  * Face detection, addressing evidence, final addressing, and turn decisions share the same event infrastructure.

  * Annotation targets remain attached to observations or frames rather than introducing a separate interaction-episode abstraction.

* Added typed perception reference contracts:

  * Added `PerceptionSourceRef` for source identity and source generation.

  * Added `PerceptionSegmentRef` for source-scoped semantic segments.

  * Added `PerceptionEntityRef` for session-level perceived entities and optionally resolved identities.

  * `EnvObservation` now carries typed source, segment, transport-participant, and entity fields.

  * Speech observations require their segment source to match their producer source.

  * Transcript observations retain their own transcript producer source while referencing the original speech segment.

  * Core lineage and identity fields are prohibited inside arbitrary observation metadata.

  * Reserved metadata validation exposes stale string-based contracts immediately instead of silently accepting inconsistent producers.

* Reworked media-source lifecycle tracking:

  * Media source state events and snapshots now use `PerceptionSourceRef`.

  * Source generations are allocated by the shared perception runtime.

  * Media-source snapshots expose typed transport-participant identity.

  * Realtime source-state updates and historical source-state projection share the same registry logic.

  * Source state can be reconstructed at a precise historical Perception Event sequence.

  * Source reconnection no longer risks merging observations from different source generations.

* Improved exact perception snapshot boundaries:

  * Added snapshot capture up to an explicit Perception Event sequence.

  * Annotation-driven user turns freeze perception at the exact turn-decision event.

  * Events arriving after a decision cannot leak into the committed turn snapshot.

  * Historical source state is projected from the previous cutoff and the retained event slice.

  * Retention gaps remain explicit and are never repaired with future live state.

* Added public interaction and turn-taking schemas:

  * Added typed interaction entity references.

  * Added addressing modes and interaction entity kinds.

  * Added `InteractionAddressingEvidence`.

  * Added final `InteractionAddressing`.

  * Added `TurnTakingEvidence`.

  * Added `TurnTakingAssessment`.

  * Added final `TurnTakingDecision`.

  * Added explicit `HOLD`, `COMMIT`, `PASSIVE`, `INTERRUPT`, `PROACTIVE_CHECK`, and `CANCEL` actions.

  * Interaction schemas remain transport- and LiveKit-independent.

* Reworked Interaction Router configuration:

  * Router configuration now owns a generic plugin `init_config`.

  * Runtime dependencies are passed through a structured `InteractionRouterDependencies` object.

  * Plugin-owned processor configuration no longer expands the framework-level Router constructor for every new processor.

  * Alternative Router plugins can define their own internal processor composition.

  * Audio activity, addressing, endpoint assessment, transcription, synthesis, and transcript synchronization remain independently configurable.

* Added revisioned multimodal turn candidates:

  * Speech frames, completed speech segments, transcripts, audio evidence, and addressing evidence are grouped into speaker-scoped candidates.

  * Candidate identity uses typed source, entity, and transport-participant references.

  * Segment ownership uses `PerceptionSegmentRef` rather than local tuple conventions.

  * Candidate revisions change whenever model-relevant evidence changes.

  * Late model results are discarded when their candidate revision is no longer current.

  * Each speaker maintains at most one latest-wins assessment task.

  * New evidence cancels obsolete logical assessments without blocking the observation consumer.

* Added an explicit Turn-Taking model boundary:

  * `TurnTakingModelBase` receives immutable evidence snapshots.

  * Models produce probabilistic assessments rather than routing actions.

  * Models cannot directly commit a user turn or trigger an Avatar response.

  * Model capabilities declare supported modalities and required evidence types.

  * Audio endpoint assessment remains independent from addressing policy.

* Added deterministic Turn-Taking policy:

  * Router policy converts endpoint and addressing assessments into final actions.

  * Audio-only turns may be treated as directly addressed to the Avatar by channel semantics.

  * Audio-visual turns require addressing evidence before committing.

  * Completed speech addressed to the Avatar produces `COMMIT`.

  * Completed speech addressed elsewhere produces `PASSIVE`.

  * Incomplete speech produces `HOLD`.

  * Unknown audio-visual addressing waits for further evidence before becoming passive.

  * Timeout behavior is mode-aware and does not blindly commit unknown audio-visual speech.

* Added local Smart Turn endpoint assessment:

  * Added a local Smart Turn v3 model adapter.

  * Smart Turn consumes immutable PCM evidence rather than relying on transcript punctuation.

  * Consecutive speech segments can be combined into one candidate-level endpoint input.

  * Temporal gaps between segments are preserved as silence.

  * Long candidates retain only the configured final audio window.

  * Smart Turn runs through an AlphaAvatar-owned persistent inference runner.

  * The same endpoint model supports audio-only and audio-visual candidates.

  * Smart Turn determines completion probability but does not determine the addressee.

* Added annotation-driven Avatar turn execution:

  * Added `AvatarTurnController`.

  * The controller independently consumes final interaction-turn annotations.

  * `COMMIT` creates one immutable `TurnSnapshot`.

  * Turn snapshots include the exact decision event, relevant input observations, actor, addressees, confidence, and reason.

  * Repeated decisions for the same input ID reuse the existing snapshot.

  * `PASSIVE`, `HOLD`, and `CANCEL` do not create Avatar user turns.

  * Background interaction can therefore remain in shared perception context without automatically triggering a response.

* Added explicit full-duplex interruption:

  * Speech-start interruption is separate from endpoint completion.

  * Audio-only interaction can interrupt immediately when user speech begins.

  * Audio-visual interaction interrupts only after evidence indicates the speaker is addressing the Avatar.

  * Interruption does not delete the active user candidate.

  * The same candidate continues collecting audio and transcripts before its eventual `COMMIT`, `PASSIVE`, or `CANCEL` decision.

  * Assistant and transient AlphaAvatar output lanes receive explicit interruption controls.

  * The temporary LiveKit response sink is explicitly interrupted when it still owns final Assistant speech playback.

* Removed LiveKit text turn detection from the active interaction path:

  * LiveKit `turn_detection` now runs in manual mode.

  * LiveKit VAD and STT are not used to decide AlphaAvatar user turns.

  * AlphaAvatar VAD produces shared speech observations.

  * AlphaAvatar STT produces transcript observations.

  * The Router produces final interaction-turn annotations.

  * The Avatar explicitly submits committed turns for response generation.

  * LiveKit remains a temporary model and final Assistant delivery adapter rather than the authority for user-turn boundaries.

* Added Addressing Evidence producers and fusion:

  * Added typed addressing-evidence kinds.

  * Addressing producers independently publish evidence rather than directly changing turn state.

  * Evidence is attached to the observation from which it was derived.

  * Speech-bound evidence can be routed through the shared segment reference.

  * Visual evidence without a speech segment can be aligned by entity, transport participant, and temporal proximity.

  * Conflicting evidence can resolve to unknown instead of forcing a target.

  * Final addressing annotations preserve evidence lineage separately from user-input observation IDs.

* Added an experimental acoustic invocation addressing producer:

  * Added an open-vocabulary local keyword-spotting path.

  * Invocation detection operates directly on speech audio rather than matching general STT output strings.

  * Avatar identities and aliases can be configured as invocation phrases.

  * Invocation results publish Avatar-directed addressing evidence.

  * Detection runs asynchronously through a persistent inference runner.

  * Bounded queues and segment-level drop handling prevent keyword inference from blocking realtime perception.

  * This acoustic path is an experimental development-stage producer and is not intended to remain the primary semantic addressing mechanism.

* Added visual orientation addressing:

  * Existing face-analysis output now exposes normalized face detections and five-point facial landmarks.

  * Visual Addressing reuses shared face annotations instead of running a second face detector.

  * Face orientation is estimated from landmark symmetry and roll.

  * Head-pose proxy values are kept distinct from true gaze estimation.

  * Orientation evidence is temporally smoothed before publication.

  * Hysteresis and republish intervals reduce frame-level evidence noise.

  * Ambiguous multi-face frames are not assigned to a speaker without entity evidence.

  * Visual orientation publishes Avatar-facing or unknown/away evidence.

  * Visual evidence acts as an auxiliary addressing signal rather than an absolute interaction decision.

* Added multimodal Addressing Fusion:

  * Invocation, visual, semantic, focus, and future explicit-channel evidence share one schema.

  * Each producer maintains its latest evidence independently.

  * Repeated evidence for the same effective target updates lineage and confidence without continuously restarting endpoint assessment.

  * Effective target changes invalidate stale assessments through candidate revisions.

  * Similar-confidence conflicts resolve conservatively to unknown.

  * Audio-visual interruption requires effective Avatar-directed evidence.

* Hardened speech transcription segment handling:

  * Speech and transcript processors now share typed segment lineage.

  * STT providers no longer reconstruct speech source identity from metadata strings.

  * Segment STT supports multiple locally buffered segments per source.

  * Realtime STT can buffer a later local segment while the current remote input buffer is being committed.

  * Segment lifecycle overlap no longer terminates an entire STT stream.

  * Rejected or discontinuous segments remain explicitly discarded.

  * Provider failures are isolated from the main speech observation consumer.

* Improved asynchronous Router execution:

  * Observation consumers never await endpoint-model inference inline.

  * Addressing producers, transcription, endpoint assessment, and Avatar turn execution operate as independent tasks.

  * Per-speaker latest-wins tasks prevent unbounded inference backlogs.

  * Candidate mutation remains synchronous and does not require an event-loop lock.

  * Inference results are validated against immutable candidate revisions.

  * Annotation and observation consumers use independent IDs and cursors.

* Preserved passive multi-user interaction context:

  * Interaction targets are represented as annotations on observations.

  * No separate `InteractionEpisode` object is introduced.

  * Different speakers can maintain independent candidates when entity or source evidence separates them.

  * Speech addressed to another participant produces `PASSIVE` instead of an Avatar reply.

  * Passive observations remain available to perception, Memory, Persona, and subsequent Avatar context construction.

  * A speaker can move from another participant back to the Avatar through later addressing evidence.

### Notes

* This document is a draft while the remaining v0.6.7 addressing work is completed.

* Semantic Addressing will replace acoustic invocation as the primary interaction-target signal before the final release.

* The planned Semantic Addressing path will use a small local CPU model over Avatar identities, aliases, conversation focus, and the current transcript segments.

* Acoustic invocation remains useful as an experimental provider, but keyword detection alone cannot reliably distinguish invoking the Avatar from discussing the Avatar by name.

* Visual orientation is not equivalent to eye-gaze estimation. Five-point landmarks provide a low-cost auxiliary head-orientation signal only.

* Accurate shared-microphone multi-speaker routing still depends on upstream speaker and entity separation.

* Visual-only proactive turn-taking will expose a public producer interface in v0.6.7, but no concrete emergency/help-detection implementation is planned for this release.

* LiveKit remains the default RTC transport.

* LiveKit `AgentSession` still owns parts of final Assistant LLM/TTS delivery during this migration.

* AlphaAvatar now owns the authoritative user-turn decision even while LiveKit remains the temporary response adapter.

* Final Assistant output ownership migration remains separate from the turn-taking work.

* Perception and output streams remain bounded realtime buffers rather than durable media stores.

* Internal APIs continue to prioritize rapid architectural iteration over backward compatibility.

### Internal Direction

v0.6.7 moves AlphaAvatar from transcription-driven turn completion toward explicit multimodal interaction decisions:

```text
RTC / Device Input
        ↓
Typed EnvObservation
        ↓
PerceptionRuntime
  ├── audio frames
  ├── speech frames
  ├── speech segments
  ├── transcripts
  ├── video frames
  ├── source-state events
  └── annotation events
        ↓
Interaction Router
  ├── Audio Activity
  ├── Speech Transcription
  ├── Endpoint Assessment
  ├── Addressing Producers
  ├── Addressing Fusion
  └── Turn Policy
        ↓
InteractionAddressing
+
TurnTakingDecision
        ↓
AvatarTurnController
        ↓
Exact TurnSnapshot
        ↓
Avatar Context / Model
        ↓
Temporary LiveKit Response Sink
```

Endpoint and addressing responsibilities are explicitly separated:

```text
Current candidate audio
        ↓
Smart Turn
        ↓
P(end of turn)

Invocation / Visual / Semantic / Focus evidence
        ↓
Addressing Fusion
        ↓
Speaker → Addressee

P(end of turn) + Addressee + Runtime Policy
        ↓
HOLD / COMMIT / PASSIVE / INTERRUPT / CANCEL
```

The planned semantic path continues this separation:

```text
Avatar identities and aliases
        +
Current conversation focus
        +
Current transcript segments
        ↓
Local Semantic Addressing Model
        ↓
P(addressed to Avatar)
        ↓
Semantic Addressing Evidence
        ↓
Multimodal Addressing Fusion
```

The architectural responsibility is now increasingly explicit:

* `avatar-core` owns transport-independent observations, annotations, ordered perception events, source identity, segment lineage, event retention, historical projection, and exact cutoffs.

* The Interaction Router owns speech routing, transcription routing, endpoint assessment, addressing evidence, evidence fusion, interruption policy, and final turn decisions.

* Voice plugins own VAD, STT, and TTS capabilities without owning user-turn policy.

* Persona owns face and speaker perception and contributes typed entity-related evidence.

* Avatar owns committed turn snapshots, context composition, model orchestration, and response initiation.

* Output Runtime owns transport-independent Assistant and transient output controls.

* Entrypoints own RTC conversion and temporary transport-specific response delivery.

* Models provide assessments and probabilities; deterministic runtime policy remains responsible for actions.

* Background and third-party interaction remains observable without automatically becoming an Avatar user turn.

v0.6.7 establishes the interaction boundary required for semantic addressing, conversation focus, multi-speaker meetings, visual-only proactive events, richer barge-in policy, and the continued removal of `livekit.agents` from AlphaAvatar-owned realtime behavior.
