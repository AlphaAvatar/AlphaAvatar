## AlphaAvatar v0.6.7 Release Notes

### Highlights

AlphaAvatar v0.6.7 reworks the flat-index path of the Memory plugin around **note-level dialog memory and configurable memory maintenance**.

Conversation memory is no longer a flat list of atomic statements. Each session now produces one **memory note** carrying a summary, standalone factual statements, and retrieval keywords. The note is the unit that gets embedded, retrieved, and updated.

This release also introduces explicit **maintenance operations**. Newly extracted memory can be added, discarded as redundant, or merged into an existing memory, and which of those are permitted is a configuration choice rather than a hardcoded behaviour.

The design follows the UnifiedMem framework (ACL 2026), which decomposes a dialog memory system into extraction, indexing and maintenance, retrieval, and answering stages. Each stage's strategy is now selected by configuration, so extending the system means adding a value to an enum rather than restructuring code.

### What's New

* Added note-level dialog memory:

  * Added `MemoryNote`, extending `MemoryItem` with `summary`, `facts`, and `keywords`.
  * A note's human-readable `value` is composed from its summary and facts, so every consumer that reads `value` — prompt rendering, markdown backup — stays correct without knowing it holds a note.
  * Notes are used for `CONVERSATION` only. Avatar, Tools, and ENV memory keep the existing item shape.
  * Tool memory is deliberately excluded: it is already aggregated at the tool-episode level, which is finer than a session, so a session-level note would merge unrelated episodes.

* Added a staged, configurable memory pipeline:

  * Added `MemoryPipelineConfig` under `memory.init_config.pipeline`, covering extraction, key organization, value source, and maintenance.
  * `maintenance.ops` is an operation set rather than a strategy name: `[add]`, `[add, noop]`, or `[add, noop, update]`.
  * `key.organization` and `key.include_topic` make the retrieval key explicit.
  * `value.source` makes the evidence unit explicit.
  * Unimplemented values raise rather than silently degrading to a default.

* Added the Add / Noop / Update maintenance stage:

  * New memory is compared against existing memory before being written.
  * Records whose nearest existing memory falls below the similarity threshold skip the model call entirely, so cost tracks the real duplication rate rather than volume.
  * Added the `search_similar_batch` vector-database operation, which resolves a whole batch of neighbour lookups in one round trip.
  * An update keeps the target's original `memory_id`, which is what makes the vector-store delete-and-reinsert behave as an upsert, and its original timestamp, because that records when the fact was observed.
  * Decision semantics follow UnifiedMem's memory-update agent, including its temporal-evolution rule: the same topic at a different point in time is a new memory, not an update of the old one.
  * Delete is deliberately not implemented. Old memories stay useful — a user may later refer to a former job or an earlier preference.

* Added composable extraction prompts:

  * The conversation prompt is assembled from fragments rather than being one fixed string.
  * Enabling keywords or the session gate adds a prompt block plus a schema field — the same mechanism in both cases.
  * The session gate is a prompt fragment rather than a separate pre-call. A standalone gate would add a round trip to every session in order to save one on the minority that hold nothing worth keeping.
  * Added `ConversationDelta` and `NotePatch` alongside the existing `MemoryDelta` and `EnvMemoryDelta`, so each of the three extraction paths has its own explicit output type rather than one field changing meaning depending on the caller.

* Separated the retrieval key from the answering evidence:

  * `flatten_records` now emits `embedding_text` alongside `page_content`.
  * `embedding_text` is what gets vectorized; `page_content` is what reaches the prompt and the markdown backup.
  * Previously a single field served both purposes, so improving retrieval necessarily polluted the prompt.
  * `topic` now participates in retrieval. It was declared "for retrieval and grouping" but entered neither the vector nor any filter.

* Added the first automated test suite:

  * The repository had pytest configured but contained no test files. This release adds a `tests/` root covering the memory changes.
  * Coverage targets logic that could plausibly break: maintenance decision mapping, note serialization round-trips, rebuilding legacy rows written before this change, prompt-fragment assembly, and pipeline configuration validation.
  * Extraction prompts and provider plumbing are deliberately not unit-tested — mocking the provider there would assert the mock rather than the behaviour.

### Fixed

* **Vector search ran on squared L2 distance rather than cosine.**

  No distance metric was specified in the LanceDB runner, and LanceDB defaults to squared L2. For embeddings that are not unit length, vector magnitude therefore leaked into semantic ranking — a vector pointing in exactly the query's direction but with twice the magnitude ranked as far away as a vector 45 degrees off.

  AlphaAvatar supports two embedding providers: OpenAI, whose embeddings are normalized, and Google/Gemini, whose output is not guaranteed to be. The metric is now pinned to cosine rather than relying on that assumption. This also makes `1 - distance` a well-defined similarity, which the maintenance threshold depends on.

### Changed

* Conversation extraction emits note-level `keywords` in place of the per-item `node_mentions` anchors, so conversation memories no longer contribute graph nodes.

  What the extractor produced there were keywords, not graph entities — the schema carries no relation field, so it could never back an entity-relation graph. Avatar, Tools, and ENV extraction keep `node_mentions` unchanged.

### Notes

* Existing memories remain readable and retrievable; they rebuild as plain `MemoryItem`. No data migration is required or provided.
* Only notes may be updated by the maintenance stage. Legacy items can trigger a noop at most, which avoids an item-to-note shape conversion.
* Notes are stored with `doc_kind="memory_item"`. That column separates memory rows from graph-node rows and is filtered on during search, so introducing a separate kind would have made notes invisible to retrieval. Note identity travels in a reserved key inside `extra_data`, which also means no new table columns and no schema migration.
* `similarity_threshold` defaults to `0.82`. This is a starting point for calibration on real data, not a tuned value. Too high degenerates to add-only; too low sends unrelated memories to the judge.
* Qdrant was not modified; its support remains paused as of v0.6.3.

### Internal Direction

The graph index is the next target. Prior analysis under the same framework indicates that the current graph construction — all-pairs co-occurrence edges, with node descriptions that are written once and never enriched — is closer to the weakest variant measured in the literature than to the strongest. Entity and relation extraction, description merging, and score-based re-ranking of graph hits are tracked separately.
