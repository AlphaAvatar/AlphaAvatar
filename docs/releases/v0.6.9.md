# AlphaAvatar v0.6.9 Release Notes

[中文](v0.6.9-zh.md)

### Highlights

AlphaAvatar v0.6.9 makes the native runtime of v0.6.8 **installable, configurable and diagnosable**. A Linux x86_64 package now carries its own Python and the `alphaavatar` command; an interactive Setup chooses what an Avatar runs with and installs exactly that; `upgrade` moves forward to a newer build beside the current one and `cleanup` removes what is no longer used. Configuration lives in named **bundles** of commented **profiles**, written from complete templates, with credentials kept by name out of the configuration files.

**`alphaavatar doctor`** checks a configuration without contacting anything, and, once agreed to, runs a short session with the configured models and services on fixed speech and image samples. It reports where a lost sentence was lost, per-stage latency, and each runner's queue and execution figures.

The realtime path is made more predictable at its boundaries. Every speech segment ends in one explicit transcription state; a final that arrives late still joins its Turn until a hard deadline, after which the Turn proceeds with a notice instead of losing the input. Turn taking accumulates speech across the pauses inside one utterance, holds explicitly when it is uncertain, and resolves the uncertainty within bounded waits.

Participants, identity and data ownership have one runtime owner: **ParticipantRuntime** tells which participants a Turn belongs to whenever that is needed. Persona associates several voices and faces in one session and uses a new speaker-vector model. Memory keeps verified owners for mixed batches, reads memories by their type and owners, and refuses to mix vectors of two embedding models in one store.

Inference runners take explicit launch inputs, and the voice activity and turn-taking runners can run **several worker processes**. Every runner reports its queue and execution metrics.

### What's New

#### Speech Transcription States, Late Results and Correlation

* Each speech segment ends in exactly one terminal transcription state: final text, an empty final, an error, rejected, closed without a final, cancelled or stale. What is logged is what downstream consumers receive.
* The transcript wait for a decided Turn now has an observation point (`transcript_wait_sec`) and a separate hard deadline (`transcript_timeout_sec`, 3 s by default). A final that arrives before the deadline joins its Turn. At the deadline the Turn is committed with a `voice.transcription_unavailable` notice, and a later final is retired rather than attached to a later Turn.
* The observation point only reports a transcript still pending. Its schema default is 0.75 s; `demo.yaml` and the profiles `config init` and Setup write set it to 3.0 s, the same as the deadline, so they report no pending transcript before the deadline.
* Speech that starts inside a voice-activity backlog gap is reported as lost and cancelled, never published truncated; new speech is accepted only after a confirmed boundary.
* Cancelling an answer while its speech is being synthesized is reported as an interruption, not as a synthesis failure; closing during final publication settles without errors.
* Segment transcription reads the service's streamed events by any line ending, reuses its connection across the segments of a stream, and loads its SDK off the event loop.
* A bounded input trace links each segment to its transcription request, terminal state, final, turn decision and committed Turn cutoff. It holds hashed identifiers and no raw text, and is limited by count, size and age.

#### Turn Taking and Addressing Across an Utterance

* Turn taking keeps one open, time-ordered input window. Pauses inside an utterance, anonymous segments and speaker labels no longer split it into separate inputs.
* Once its speech is complete, an input is sealed and waits for its transcripts while the next input is already being collected. Both stages are bounded (`max_pending_inputs`, `max_window_segments`).
* HOLD decisions name their reason: speech incomplete, speech completion uncertain, addressing uncertain, or waiting for a transcript.
* Uncertainty is resolved within bounded waits (`speech_completion_wait_sec`, `addressing_wait_sec`). An input committed at such a deadline carries a notice that its completion or its addressing was uncertain.
* Progress advances only on an actually committed Turn; a proposal that arrives after its commit deadline (`commit_timeout_sec`) is rejected.
* Semantic addressing reads the conversation since the last committed Turn, and its wait starts when the transcript it needs is available.
* Turn notices reach the model's context: speech that could not be transcribed stays in history as unavailable speech, and the model is told to follow instructions only from the latest user message.

#### Participants, Identity and Persona

* **ParticipantRuntime** owns the association of speech segments and faces with session participants, and tells a Turn's participants from its own input whenever they are needed, instead of fixing them at admission. A settled association is kept for the whole session, so readers that run later, such as Memory at the session's end, see it.
* A voice or a face is one entity for the whole session, across devices and source generations.
* Several faces in one frame are taken nearest first; on the primary participant's device, the nearest new face is the primary participant's.
* The speaker-vector model is now **CAM++ (zh-en)**, exported to ONNX (about 28 MiB) and downloaded when its runner first initializes.
* Speech shorter than one second is not matched alone: its audio is carried into the next segment from the same source.
* Stored voiceprints and face vectors are updated by a weighted merge with each session's vectors rather than replaced.
* Identity match thresholds are Persona settings: `speaker.identity_match_threshold` (0.6, a cosine of CAM++ vectors) and `face.identity_match_threshold` (0.40).

#### Memory Ownership, Recovery, Retrieval and Embedding Spaces

* A memory batch that contains unattributed speech keeps its verified users as owners.
* Retrieval reads a memory by its type and owners, never by its scope: Avatar memory is readable by every participant, while conversation, tool and environment memory is readable only by its user owners, from any context.
* A failed environment-memory batch is retried for its own range only: it never absorbs newer input, never commits past a gap, and replaying stored work cannot move a newer checkpoint back.
* Passive retrieval is bounded by `retrieval.passive_timeout_sec` (3 s) and skips the embedding request when there is nothing to retrieve.
* **Embedding-space protection:** each text-vector store records the embedding model that made it. When the Host opens a store, another model, or vectors of another size, is refused before anything in the store changes. Several Hosts opening a new store at once settle on one record.
* Setup checks ahead only what existing local LanceDB records tell: a bundle naming another model for such a store is refused before anything is installed. A Qdrant store, the actual vector size, and whatever the records cannot tell are checked when the store is opened. A store made before records were kept is accepted only at its own vector size, and recorded as assumed.

#### Inference Runners, Parallelism and Metrics

* Each runner receives an explicit launch record (workspace, model directory and its configuration) instead of reading store or tool settings from the process environment.
* `runtime.inference.methods.<method>.workers` (1 to 8, default 1) runs several independent worker processes, each with its own model copy, for a runner that declares itself replicable. In this release those are Silero VAD and Smart Turn v3; a worker count for any other runner is refused when the configuration loads.
* Requests wait in a bounded first-in, first-out queue per method, with separate queue, execution and client deadlines. A request is never replayed after a worker is killed or times out.
* A failed worker is rebuilt while the method's other workers keep serving. Restarts are limited per method (`restart_limit` within `restart_window_seconds`); once the limit is used up, the Host stops with an error rather than restarting without end.
* Per-method metrics in the Host health report: workers, ready workers, executing and waiting requests, rejections, queue and execution timeouts, and restarts.

#### Configuration, Credentials and Interactive Setup

* Configuration is organized as **bundles** (one file naming its profiles) and **profiles** (one file per section) under the application home, with a default bundle in the application settings.
* `alphaavatar config init <bundle> --avatar-id <id>` writes a complete, commented set of profiles from templates based on the reference `demo.yaml`; it never overwrites an existing file.
* `alphaavatar config check [--json]` loads a configuration as `start` would, without contacting anything. It names the setting at fault, a variable that holds no value, and the setup command for a plugin that is not installed.
* `alphaavatar setup` asks for capabilities, then each running part's provider and model, then the credentials it needs, and shows a grouped summary before installing. It writes the bundle with every comment of the templates kept.
* `alphaavatar setup <bundle>` installs what an existing bundle's settings need, without asking again for capabilities, models or credentials. On a terminal it still shows the summary and asks `Install and enable?`; without one it runs unattended. `--plan` prints the plan as JSON. Existing bundles, profiles and stored credentials are never overwritten.
* Credentials are read from the environment, then from the `.env` file `ENV_FILE` names, then from the stored credentials file (mode 0600). A blank value counts as unset, and logs and reports name credential variables, never their values.
* A server of one's own keeps its key in a variable named after its URL, which only that server may read.

#### Standalone CLI, Linux Package, Upgrade and Cleanup

* A Linux x86_64 base package (glibc 2.28 or newer) carries its own CPython 3.13 and the `alphaavatar` command. Setup then installs the packages a bundle needs into a separate environment and checks it; model weights are downloaded into the model cache when their runners first initialize.
* `install.sh` installs the latest release by default, or a given `--version`, `--file` or `--url`, and checks each download's SHA-256.
* The installer adds the command's directory to `PATH` for new terminals, in a marked block of the user's shell startup files; its `Next` lines say what makes the command found in the terminal it ran in. After a first installation on a terminal, it offers to run Setup; a Setup that fails or is cancelled leaves the installation in place.
* `alphaavatar upgrade [--check | --version | --file]` prepares and validates the target build beside the current one, then switches to it in one step. A failure at any point before the switch leaves the current installation unchanged.
* **`upgrade` only moves forward. This release provides no rollback or downgrade.**
* `alphaavatar cleanup [--dry-run]` removes only the builds and environments the installer made that the current installation no longer uses; application data is never touched.

#### Doctor and CLI Display

* `alphaavatar doctor [bundle] [--rounds N] [--no-metrics] [--json] [--list]` runs static checks first, which create, download and contact nothing.
* With agreement on a terminal, or `host.doctor.external_services: true` without one, it starts the runtime as `start` does, in a temporary workspace and without RTC. It then runs one fixed scenario (voice, or voice and vision) for a number of rounds.
* Every round is checked against strict expected answers. A lost sentence is attributed to voice activity detection, transcription, turn taking, or unknown.
* Reports show the stages from the end of speech to the first audio frame, a transcription timing breakdown, and each runner's workers, longest queue wait and longest execution. The first round is reported apart; later rounds are summarized by median and range.
* The diagnosis session's data and its local vector stores go to a temporary workspace, removed afterwards. Models downloaded on a first run stay in the configured model cache. A remote vector store may hold real data, so the diagnosis runs with one only when the configuration marks its remote stores as test stores; what it writes there is not removed with the temporary workspace.
* Text and JSON reports pass through the same output boundary as `config check`: credentials from the configuration and the environment are replaced and control characters removed before anything is printed or exported.
* All commands share one report layout. Group titles and states worth noticing are colored on a terminal; the width follows the terminal and long values wrap under their column. `NO_COLOR`, `TERM=dumb`, pipes and files get the same text, plain.

### Installation

**Linux package (recommended):** on Linux x86_64 with glibc 2.28 or newer,

```bash
curl -fsSL https://github.com/AlphaAvatar/AlphaAvatar/releases/latest/download/install.sh | bash
```

The installer asks whether to run `alphaavatar setup` right away. The command is on `PATH` for new terminals; in the terminal the installer ran in, follow its `Next` lines, or open a new terminal, then:

```bash
alphaavatar doctor
alphaavatar start
```

Run `alphaavatar setup` yourself only when the installer's Setup was skipped or did not finish.

v0.6.9 is the first release that publishes the Linux package files the installer reads. A given version, a downloaded package or an offline mirror is installed with `install.sh --version`, `--file` or `--url`; see [DEPLOY.md](../DEPLOY.md) and the [CLI guides](../cli/README.md).

**From source:** for development, clone the repository and use the committed lockfile (`uv sync --all-packages --locked`); for a release's source, check out its tag. Source checkouts are updated with git, not with `alphaavatar upgrade`.

**PyPI:** publishing individual packages to PyPI is a separate, manual workflow. A GitHub Release does not mean that all 16 workspace packages, or their matching versions, are on PyPI.

### Upgrading from v0.6.8

v0.6.8 published no Linux package, so a v0.6.8 source checkout moves to v0.6.9 from source, or by installing the v0.6.9 package and setting up a bundle. Internal contracts and some settings changed without compatibility aliases:

* **`avatar.id` is required.** The workspace is `avatar.workspace_root` (the complete directory) or the default under the application home (`ALPHAAVATAR_HOME` or `application.home`). The model cache is `application.cache_root`. `avatar.work_dir`, `AVATAR_WORK_DIR` and `ALPHAAVATAR_MODEL_CACHE` are refused with a message naming their replacement.
* The health server binds to `127.0.0.1` by default (previously `0.0.0.0`).
* `voice.vad.min_silence_duration` defaults to 0.3 s (previously 0.55 s). Speech closes about a quarter of a second sooner; speech with longer pauses is sent to transcription in more segments, so it can take more transcription requests.
* Turn-taking settings changed, and unknown names are refused:
  * `max_hold_sec` is now `speech_completion_wait_sec`;
  * `policy.commit_threshold` is replaced by `model.incomplete_threshold` and `model.complete_threshold`;
  * `transcript_timeout_sec` and `commit_timeout_sec` are new.
* `runtime.engine.max_turn_candidates` is now `max_turn_inputs`.
* Persona's speaker vectors come from the new model and are stored in a new collection. Voiceprints stored by v0.6.8 are not searched, and voices are learned again.
* Memory visibility follows the type-and-owner rule above; existing records are not migrated. A conversation or tool memory whose only owner is the Avatar is no longer returned to anyone.
* A text-vector store is refused when the configured embedding model differs from the one recorded for it. Give the store another name for a separate index, or configure the model it was made with; nothing is deleted or rebuilt automatically.

### Validation

Evidence for this release comes from four kinds of checks, reported separately:

* **Offline tests.** The offline suite (about 1,200 tests) runs in the Quality workflow on every push and pull request, together with lock, workspace, lint, format, build and installation checks. Changes to data ownership, lifecycle, identity and storage contracts were also checked by mutation: each protection was removed in turn to confirm that a test fails without it.
* **Synthetic stress and soak tests.** These use model-free stand-in runners on a shared development machine. They measure scheduling, queueing, cancellation and recovery, and their throughput figures are not model, provider or device performance.
  * A 30-minute concurrency soak (4 sessions × 3 methods) completed every request exactly once, with no loss or duplication.
  * Repeated worker kills and repeated runtime start and stop were recovered from, with every child process, descriptor and socket reclaimed.
  * With a fixed 5 ms stand-in execution and a sustained backlog, two workers roughly doubled the throughput of one.
* **Doctor runs with real services.** These ran with the configured models and services on one development machine, using Doctor's fixed samples, at 5 rounds per report.
  * Utterances that pauses split into two or three segments were committed as one input: 40 of 40 rounds, over four samples and two silence settings, committed exactly one Turn, without an early reply or a lost segment. The sentences missing in some rounds were missing from the transcription service's text (see Known Limitations).
  * With the default configuration, the voice-and-vision scenario passed 5 of 5 rounds. The voice-only scenario passed none of 5: four rounds lost the second sentence in the transcription service's text, and in one the final arrived after the 3 s deadline, so the Turn was committed with its notice, as designed.
  * Two stages became shorter in every round (medians of the later 4 rounds): the end of speech to voice-activity close by 240 to 260 ms, from the new silence default; and, only when there is no eligible memory to recall, a committed Turn to its prepared context by about 240 ms. The wait of about 0.5 s between a final and its commit, for uncertain addressing, is unchanged.
  * End-to-end time to first audio also includes transcription, model and speech-synthesis variation between runs, so **no end-to-end latency gain is claimed**, and stage medians are not summed into one.
* **Manual acceptance.** The maintainer accepted real calls, the package installation and Setup.

The Linux package workflow builds the package in `manylinux_2_28` and installs it on a clean Ubuntu 24.04 container without Python, Node or compilers. Release candidates were also checked in a clean Ubuntu 24.04 root filesystem with fictional credentials: the installer ran into a real Setup of the reference bundle (105 packages, about 514 MB, all runners validated), and an upgrade from an earlier CI build and a cleanup completed with application data unchanged.

### Known Limitations

* Linux x86_64 only. The package is built to need glibc 2.28, but installation has been run only on Ubuntu 24.04 (glibc 2.39). Semantic addressing needs an x86-64-v3 CPU. The installer does not support Windows, macOS or mobile.
* No rollback or downgrade. `cleanup` does not detect a running Host: stop every `alphaavatar start`, `dev` and `doctor` first.
* Setup does not install RAG or Character. Neither `config check` nor Doctor contacts the RTC server: LiveKit credentials are first used when `start` or `dev` connects.
* On Doctor's fixed two-sentence sample, the default segment transcription model (`gpt-4o-transcribe`) often returns only the first sentence (both sentences in 7 of 20 runs), and Doctor reports such rounds as failed. The loss is in the service's returned text. The other supported models transcribed that sample fully but did worse on multilingual and mixed-language speech, so the default is kept.
* Transcription services may invent text for silence or noise sent without voice activity detection; through the normal voice-activity path, the silence and noise samples formed no speech segment.
* An unavailable-speech notice relies on the model following only the latest user message; this was checked with one model (`gpt-5.6-luna`) and should be checked again with another.
* Persona speaker and face matching was evaluated offline on public Chinese and English recordings only. Identity in sessions with several people remains in progress: similar voices can be bound to the same user, one person's voice can be split across users, and a track that mixed in another voice before its recognition saves that voice to the recognized user.
* Short speech is carried into the next segment, so a session's last short phrases may stay unattributed. Memory extracted from a batch mixing an unrecognized speaker with a verified user is owned by the verified user, and a batch with two verified users is owned by both.
* Environment memory committed before a new participant is recognized stays with that participant's temporary identity, and a session's last environment observations may not be written when its shutdown timeout is reached.
* Concurrent first use of a store by several Hosts was validated for LanceDB and for Qdrant's in-memory client; it was not run against a Qdrant server or a replicated cluster, where it depends on the cluster's consistency settings.
* Doctor runs one fixed scenario. It does not cover devices, RTC delivery, camera addressing, parallel workers or long runs.
* The installed base runtime recompiles some standard-library bytecode on first use, and writes it into the installed base directory.

### Not Included

* A web, mobile or desktop App, and a terminal UI. The App remains planned work.
* Streaming transcription that overlaps the speaker's speech by default, synthesis that starts at the first short sentence, and pre-established provider connections. These are latency work after this release.
* Persistent Episodes, durable Context, pause/resume and recovery, and session reconnection.
* Automatic migration or rebuilding of Memory records, voiceprints or vector indexes.
* The planned `alphaavatar test` capability-test command.

### Notes

* The default face models, InsightFace `buffalo_l`, are licensed for non-commercial research use only; commercial use needs InsightFace's permission. Check this before deploying Persona face recognition.
* LiveKit remains the implemented RTC backend; the generic backend contracts do not imply other implementations.
* Internal contracts continue to favor coherent evolution over backward compatibility.

### Architecture Direction

v0.6.9 turns the native runtime into something a person installs, configures and checks:

```text
install.sh ── base package (CPython 3.13, alphaavatar)
                 |
                 +-- config init / setup ── bundles and profiles, stored credentials
                 |                            |
                 |                            v
                 |                     plugin environment (plan, install, validate)
                 +-- doctor ── static checks ── runtime diagnosis (fixed samples, metrics)
                 +-- upgrade / cleanup ── forward switch, removal of unused builds
                 +-- start / dev
                        |
                        v
                   AvatarHost
                    +-- InferenceRuntime (shared runners, workers, metrics)
                    +-- execution: AvatarRuntime and AvatarEngine
                                     +-- ParticipantRuntime (participants of each Turn)
                                     +-- Router / Memory / Persona / Tools
```

**Next:** v0.6.10 brings configurable Persona profile detail and the product interface into the Avatar App; later releases consolidate the documentation and demo, unify identifiers and references, and introduce persistent Avatar execution.
