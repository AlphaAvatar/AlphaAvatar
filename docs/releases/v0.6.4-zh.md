## AlphaAvatar v0.6.4 发布说明

[English](v0.6.4.md)

### 亮点

AlphaAvatar v0.6.4 首次为**实时多模态感知和在线 ENV 记忆**建立完整的基础。

本版本新增与传输无关的 `avatar-core` 媒体与感知运行时，统一 Vision、Persona 和 Memory 的实时视觉输入，并把会话作用域的运行时依赖移入共享的 `AvatarRuntime`。

由此形成更清晰的全双工架构：媒体只发布一次，经标注丰富，在共享时间线上对齐，再由多个运行时插件各自独立消费。

### 新增内容

* 新增 `avatar-core` 感知架构：

  * `env` 定义 `EnvObservation` 和 `EnvAnnotation`。
  * `media` 定义 `MediaPayload`、`PayloadFormat`、`PayloadView` 以及通用的视频帧表示。
  * `perception` 提供类型化流、观测与标注的对齐、共享时间线和各消费者专属的窗口。
  * Core 媒体类型不再依赖 LiveKit、模型供应商或插件实现。

* 新增多表示媒体载荷：

  * 一条观测可以携带原始、带标注和派生的表示。
  * 渲染标注时，原始载荷保持不变。
  * 消费者显式请求所需的载荷格式和视图。
  * 视频帧使用 AlphaAvatar 自有的帧类型，不再在 Core 观测中直接保存 `rtc.VideoFrame`。

* 新增 `PerceptionRuntime`：

  * 提供相互独立的视频、音频、屏幕、事件和标注流。
  * 每个消费者维护自己的流游标。
  * 观测与标注按 `observation_id` 和 `frame_id` 对齐。
  * `PerceptionWindowBuilder` 为 Memory、Persona、Vision 和未来的路由器构建有序的多模态窗口。
  * 可选的宽限期让异步标注能在下游消费之前到达。

* 新增 `AvatarRuntime`：

  * 聚合 `SessionRuntime`、`StateRuntime` 和 `PerceptionRuntime`。
  * 使这三个运行时成为 Avatar 会话中明确的并列组件。
  * 让 `AvatarEngine` 专注于编排、prompt 组装、状态和模型轮次流程。

* 简化运行时插件生命周期：

  * 运行时依赖在构造插件时注入。
  * `on_start()` 和 `on_stop()` 不再接收运行时参数。
  * 感知消费者先于 RTC 生产者启动，生产者先于消费者停止。
  * Persona 现在完全负责其人脸流的生命周期。

* 新增与传输无关的 LiveKit 视频接入：

  * `LiveKitVideoInput` 把 LiveKit 帧转换为通用的 AlphaAvatar 视频载荷。
  * 原始视频帧和 JPEG 表示只发布一次到 `PerceptionRuntime`。
  * 未来的 RTC 适配器可以发布相同的 Core 载荷类型，无需改动 Memory、Persona 或 Vision。

* 新增带标注的视觉载荷视图：

  * Persona FaceStream 消费原始 JPEG 观测，用于人脸检测和身份匹配。
  * 人脸结果作为 `EnvAnnotation` 记录发布。
  * 标注渲染器生成带标注的视频帧和 JPEG 视图，不覆盖原始媒体。
  * 多个标注渲染器可以在同一条观测上叠加组合。

* 新增在线 ENV 记忆提取：

  * Memory 周期性地从 `PerceptionRuntime` 消费有序的观测窗口。
  * ENV 提取优先使用带标注的 JPEG 证据，没有时回退到原始 JPEG 证据。
  * 已配置的多模态 Provider 可以为 `MemoryType.ENV` 生成 `EnvMemoryDelta` 条目。
  * 会话更新时，ENV 记忆与对话和工具记忆合并。
  * `env_delta_task` 仍是可选项，禁用时安全地返回空 delta。

* 更新 Sampled Frame Vision：

  * Vision 异步消费观测，存入有界的本地缓冲区。
  * 快照保留对共享观测的引用，而不是复制已解析的帧。
  * 因此，注入视觉上下文时，迟到的标注也能用上。
  * 通用的 Core 视频帧只在模型适配器边界才转换回 LiveKit 帧。

### 说明

* LiveKit 仍是默认的 RTC 后端，但新的 Core 感知路径不再与 LiveKit 类型耦合。
* 音频、屏幕、事件和标注已有各自专用的流基础，而首个完整实现集中在实时视频。
* v0.6.4 的 ENV 检索提供初步的视觉历史基础；更丰富的对象级和图感知视觉搜索将在后续版本中继续推进。
* 使用 `PerceptionBus`、`rendered_payload` 或 `model_payload` 的现有集成必须迁移到 `PerceptionRuntime` 和显式的载荷视图。

### 内部方向

v0.6.4 建立新的实时感知路径：

```text
RTC / Device Adapter
        ↓
EnvObservation + MediaPayload
        ↓
PerceptionRuntime
  ├── Typed Streams
  ├── Shared Timeline
  └── Window Builder
        ↓
Persona / ENV Memory / Sampled Frame Vision / Future Routers
```

架构职责现在更加清晰：

* RTC 适配器对外部媒体做归一化。
* `avatar-core` 负责与传输无关的观测、载荷、流、时间线和窗口。
* `avatar-agents` 负责运行时组合与编排。
* 插件消费共享的感知数据，不直接订阅 RTC 轨道。
* Provider 接收显式的、可直接供模型使用的表示，而不是运行时的传输对象。
