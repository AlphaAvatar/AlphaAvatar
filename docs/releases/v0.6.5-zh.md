## AlphaAvatar v0.6.5 发布说明

### 亮点

AlphaAvatar v0.6.5 引入新的**共享音频感知、交互路由与隔离推理架构**。

本版本把 v0.6.4 引入的 `PerceptionRuntime` 基础从视觉感知扩展到实时语音管线。音频现在只发布一次，由 Interaction Router 切分为派生的语音观测，再由转写、说话人识别、Persona 和未来的音频处理器各自独立消费。

v0.6.5 还把此前经由 LiveKit 串行推理执行器运行的共享 AlphaAvatar 工作负载，改由 AlphaAvatar 自有的运行时承载。VAD、说话人识别、人脸分析和 AlphaAvatar 的全部 VDB 后端现在都在专用的常驻进程中运行。

由此形成更模块化的全双工架构：原始感知、派生感知、本地推理和交互编排的职责清晰分离。

### 新增内容

* 新增 Interaction Router 架构：

  * 引入 `InteractionRouterRuntime`，作为原始感知流与派生交互流之间的处理层。
  * 新增 `RouterProcessorBase`，供各自独立管理的感知处理器使用。
  * 新增 `AudioActivityProcessor`，消费原始音频、运行 VAD，并发布被接受的语音观测。
  * 新增 `SpeechTranscriptionProcessor`，消费经路由的语音并发布归一化的转写事件。
  * Router 处理器按注册顺序启动，按相反顺序停止。
  * VAD 和 STT 仍是 Voice 插件的能力，由 Router 负责编排它们。

* 新增经由 `PerceptionRuntime` 的共享音频接入：

  * `LiveKitAudioInput` 把归一化的音频帧发布到 `PerceptionRuntime.audio`。
  * 原始 RTC 音频只发布一次，由各个独立消费者共享。
  * 音频消费者不再需要直接订阅 LiveKit 轨道。
  * 每个消费者维护自己的感知游标。
  * 派生的语音帧和已完成的语音片段发布到 `PerceptionRuntime.speech`。
  * 下游消费者可以识别并忽略重复的前置缓冲帧。

* 新增 AlphaAvatar 原生的 VAD 抽象：

  * 新增异步的音频帧提交和语音活动事件流。
  * 新增可配置的激活和停用阈值。
  * 新增最短语音时长和最短静音时长。
  * 新增围绕检测到的语音保留前置缓冲。
  * 新增有界输入队列和推理超时保护。
  * 新增 AlphaAvatar 的 Silero VAD 实现。
  * Router 的语音切分现在使用 AlphaAvatar VAD 路径，不再依赖 LiveKit Agent 内部的 VAD 节点。

* 新增 AlphaAvatar 原生的 STT 抽象：

  * 新增归一化的中间和最终转写事件。
  * 新增 `openai_realtime`，用于长期保持的流式转写连接。
  * 新增 `openai_segment`，用于转写已完成的经路由语音片段。
  * 新增非阻塞的帧和片段提交。
  * 新增在供应商实现内部完成的音频重采样。
  * 新增连接恢复和平滑关闭行为。
  * 为每个音频来源独立创建转写源。
  * AlphaAvatar 转写事件暂时桥接为 LiveKit 语音事件，供现有的轮次管线使用。

* 新增 AlphaAvatar 推理运行时：

  * 新增 `InferenceRunner`，作为本地推理工作负载的注册与实现契约。
  * 新增 `InferenceRuntime`，作为由 Worker 持有、负责管理 runner 进程的运行时。
  * 新增 `InferenceExecutor`，作为会话作用域的异步推理客户端。
  * 每个推理 runner 在自己的常驻进程中只初始化一次。
  * Job 进程通过 Unix 域套接字与 Worker 的推理运行时通信。
  * 持久的方法连接在整个会话中复用。
  * 发往同一 runner 的请求仍串行执行，不同 runner 之间独立执行。
  * 较慢的说话人、人脸或 VDB 请求不再阻塞对延迟敏感的 VAD 推理。
  * runner 的启动、健康检查、超时处理、关闭和临时 socket 清理均由 AlphaAvatar 管理。

* 将 AlphaAvatar 推理工作负载迁出 LiveKit 共享推理执行器：

  * 迁移 Silero VAD 推理。
  * 迁移说话人向量推理。
  * 迁移说话人属性推理。
  * 迁移 Persona 人脸分析。
  * 迁移 Persona 的 LanceDB 和 Qdrant runner。
  * 迁移 Memory 的 LanceDB 和 Qdrant runner。
  * 迁移 MCP 的 LanceDB 和 Qdrant runner。
  * AlphaAvatar 的全部 VDB 工作负载现在都经由 AlphaAvatar 推理运行时执行。
  * LiveKit 的推理执行器只保留给 LiveKit 自有的兼容组件，例如当前的轮次检测器。

* 更新 Persona 说话人识别：

  * 说话人识别现在消费 `PerceptionRuntime.speech` 中经路由的观测。
  * 说话人处理不再依赖 LiveKit Agent 的 VAD 切分。
  * 传入的 20 ms 语音帧累积成数秒长的滚动窗口。
  * 说话人向量推理按可配置的步长间隔运行，而不是每个音频帧运行一次。
  * 说话人属性的评估频率低于说话人身份。
  * 待处理推理队列优先处理最新可用的说话人窗口。
  * 过期窗口会被丢弃，避免说话人推理逐渐落后于实时输入。
  * 说话人向量推理和说话人属性推理在相互独立的进程中运行。
  * 查询持久的 Persona 存储之前，先将说话人 embedding 与会话缓存匹配。
  * 识别出的持久身份会被加载，并与尚未解析的会话画像合并。

* 更新 Persona 人脸识别：

  * 人脸观测通过共享的 `PerceptionRuntime` 消费。
  * 感知消费与人脸模型推理分离。
  * 帧被转入只保留最新帧的有界队列。
  * 在较慢的人脸推理开始之前提交消费者游标。
  * 人脸分析现在在自己的常驻推理进程中运行。
  * 人脸向量和属性发布回 Persona 缓存。
  * 人脸标注附加到原始观测上。
  * 带标注的载荷视图单独渲染，不修改原始媒体表示。

* 更新 Persona 画像持久化：

  * `ProfilerRuntime` 现在接收会话的 `AvatarRuntime`。
  * Persona 画像的加载、搜索和保存操作使用 `AvatarRuntime.inference`。
  * 配置解析之后，才选择已配置的 Persona VDB runner。
  * LanceDB 和 Qdrant 后端在 `InferenceRuntime` 启动前动态注册。
  * 画像详情、运行时状态、说话人向量和人脸向量继续共用同一个持久的 Persona 身份。
  * 在各模态不冲突时，会话中收集的说话人或人脸证据可以合并到已解析的持久画像中。

* 更新 Sampled Frame Vision：

  * Vision 分别独立消费 `video` 和 `screen` 观测。
  * 观测被转入有界的本地快照缓冲区。
  * 本地取得所有权后立即提交感知游标。
  * 快照保留对共享观测的引用，而不是提前复制已解析的媒体。
  * 因此，向 LLM 注入上下文时，迟到的人脸或视觉标注也能用上。
  * 带标注的载荷在注入模型时才解析。
  * 较慢的 LLM 执行不再占住共享的感知游标。

* 重构在线 ENV Memory 调度：

  * 观测截取与较慢的多模态提取分离。
  * 截取的观测转入本地的待处理批次。
  * 在模型推理开始之前提交感知游标。
  * 周期性 ENV 更新和用户轮次触发的更新共用同一个调度器。
  * 成功的触发截取会刷新周期计时器。
  * 提取正在运行时，待处理批次会被合并。
  * ENV 提取仍串行执行，避免状态更新相互重叠。
  * 重试行为有上限。
  * 会话关闭时排空待处理的 ENV 工作。
  * 只有在已配置的视觉或音频证据可用时才生成 ENV Memory。
  * 用户文本可以为观测提供上下文，但不会单独产生 ENV 记忆。

* 强化共享感知的消费者模式：

  * 消费者等待属于自己的待处理观测。
  * 所需数据转入本地状态或有界的本地队列。
  * 所有权转移后立即提交消费者游标。
  * 共享游标推进之后，较慢的模型推理独立运行。
  * 每个模块都可以处理同一条观测，而不阻塞其他消费者。
  * 下游处理跟不上时，有界队列显式丢弃过期工作。
  * 出现感知缺口、无法再保证连续性时，清除本地的滚动状态。

* 更新运行时组合与生命周期：

  * `AvatarRuntime` 现在聚合 `SessionRuntime`、`StateRuntime`、`PerceptionRuntime` 和 `InferenceExecutor`。
  * Router、Persona、Face、Speaker、Profiler、Memory 和 MCP 消费者共享同一个会话作用域的 `InferenceExecutor`。
  * 运行时插件在会话推理执行器关闭之前停止。
  * RTC 来源先于 Router 处理器和下游感知消费者停止。
  * Worker 级的推理 runner 进程跨各个会话保持存活。
  * Worker 关闭时，关闭所有 runner 进程并移除推理 socket。

* 新增更清晰的来源、处理器和接收端启动顺序：

  * Persona、Memory 和 Vision 消费者最先启动。
  * 下游消费者就绪后，Interaction Router 处理器再启动。
  * LiveKit 音频和视频来源最后启动。
  * 关闭按相反方向进行。
  * 这可避免在消费者就绪之前发布观测。
  * 也可避免在处理器和接收端关闭期间有新观测进入系统。

### 说明

* 在 v0.6.5 中，LiveKit 仍是默认的 RTC 后端。
* LiveKit 继续管理 RTC 传输、用户打断处理、轮次检测、用户轮次提交、LLM 执行和 TTS 播放。
* AlphaAvatar 运行自己的 Silero VAD 来完成 Router 语音切分，同时暂时保留 LiveKit VAD，供当前的打断和轮次检测管线使用。
* AlphaAvatar 的 STT 结果暂时通过 STT 桥接转换为与 LiveKit 兼容的语音事件。
* AlphaAvatar 的全部 VDB runner 已迁移到新的 AlphaAvatar 推理运行时。
* 剩下的 LiveKit 推理进程只供 LiveKit 自有的兼容组件使用，不再承载 AlphaAvatar 的 VAD、Persona、Memory、MCP、人脸、说话人或 VDB 工作负载。
* 本地说话人和人脸模型在 CPU 上仍可能需要数百毫秒。除非处理时间超过配置的推理节奏、导致待处理工作堆积，否则这不再视为实时性失败。
* 直接实例化 Persona Profiler、Face、Speaker、VAD 或 VDB 组件的现有集成，必须通过更新后的插件路径提供共享的 `AvatarRuntime` 或其会话推理执行器。
* 现有 Voice 配置应把 STT 插件名迁移为 `openai_segment` 或 `openai_realtime`。

### 内部方向

v0.6.5 把 v0.6.4 的共享感知架构扩展到音频处理、交互路由和本地推理隔离：

```text
RTC / Device Adapters
        ↓
EnvObservation + MediaPayload
        ↓
PerceptionRuntime
  ├── audio
  ├── speech
  ├── video
  ├── screen
  ├── events
  └── annotations
        ↓
Interaction Router
  ├── Audio Activity
  └── Speech Transcription
        ↓
Persona / ENV Memory / Sampled Frame Vision / Agent Turn Pipeline
```

本地推理现在走一条由 Worker 持有的独立路径：

```text
Session / Job Process
        ↓
AvatarRuntime.inference
        ↓
InferenceExecutor
        ↓
Unix Domain Socket
        ↓
InferenceRuntime
  ├── Voice VAD Runner
  ├── Speaker Vector Runner
  ├── Speaker Attribute Runner
  ├── Face Analysis Runner
  ├── Persona VDB Runner
  ├── Memory VDB Runner
  └── MCP VDB Runner
```

架构职责现在更加清晰：

* RTC 适配器对外部媒体做归一化，并只发布一次。
* `avatar-core` 负责与传输无关的观测、载荷、流、标注、时间线和消费者游标。
* Interaction Router 把原始感知转换为派生的语音和转写事件。
* `avatar-agents` 负责运行时组合、生命周期顺序、交互编排和推理客户端。
* `InferenceRuntime` 负责常驻的本地模型和 VDB 进程。
* 插件消费共享的感知流和共享的推理服务，不直接依赖 LiveKit Agent 的内部实现。
* 较慢的模型推理与共享感知游标的推进相互隔离。
* LiveKit 目前仍是轮次决策、LLM 执行和 TTS 的兼容层。
* 后续版本将把轮次管理移入 Router，移除临时的 STT 桥接和重复的 VAD 路径，并通过 AlphaAvatar 自有的交互运行时发布归一化的交互事件。
