# AlphaAvatar v0.6.6 — Development Report

> **Status:** Development snapshot
> **Theme:** User experience, runtime convergence, transport decoupling, and full-duplex output foundations
> **Snapshot date:** August 3, 2026

## Overview

AlphaAvatar v0.6.6 is focused on improving real-time user experience while continuing the architectural transition away from `livekit.agents` as the owner of AlphaAvatar’s runtime behavior.

The work completed so far introduces a transport-independent, time-aligned output runtime; separates semantic status state from user-visible speech; moves input and output routing decisions into the Interaction Router; adds staged concurrent plugin lifecycle management; and establishes an interruptible transient speech path whose text follows actual audio playout.

The final Assistant response is intentionally still owned by LiveKit `AgentSession` in v0.6.6. It is mirrored into `OutputRuntime` for timeline alignment and transient-output interruption, but its final text and TTS delivery have not been migrated.

## Completed Work

### 1. Multimodal model configuration adjustment

The multimodal example configuration was updated away from `gpt-4o-mini` to improve instruction following, context retention, tool calling, and behavior when visual frames are present.

This addresses the observed degradation where enabling video input caused the model to over-focus on visual context and perform worse on conversation history and tool use.

The visual injection strategy remains a separate optimization area and should continue moving toward relevance-aware frame injection rather than unconditional frame insertion.

### 2. AvatarEngine lifecycle and readability refactor

`AvatarEngine` was reduced toward a composition and orchestration role.

The refactor introduced:

- staged runtime plugin lifecycle management;
- concurrent startup and shutdown within each dependency-safe phase;
- ordered lifecycle barriers between output transports, perception consumers, the Interaction Router, and RTC inputs;
- startup rollback when a plugin fails;
- best-effort shutdown that continues closing independent components after an error;
- extracted model-call context preparation and delayed status coordination;
- extracted AlphaAvatar STT-to-LiveKit transcription adaptation;
- clearer ownership boundaries between the Engine, Router, runtime plugins, and transport adapters.

The current lifecycle order is conceptually:

```text
Startup:
RTC output adapters
    ↓
Persona / Memory / Vision consumers
    ↓
Interaction Router processors
    ↓
RTC input adapters

Shutdown:
RTC input adapters
    ↓
Interaction Router processors
    ↓
Persona / Memory / Vision consumers
    ↓
RTC output adapters
```

Plugins inside the same phase can start or stop concurrently. Dependency-sensitive phases remain sequential.

### 3. Runtime plugin lifecycle contract

`AvatarRuntimePlugin` now acts as a required session lifecycle contract.

Runtime plugins explicitly implement:

```python
async def on_session_start(self) -> None: ...
async def on_session_stop(self) -> None: ...
```

This prevents newly added session-scoped plugins from silently omitting resource initialization or cleanup behavior.

### 4. LiveKit transport boundary moved toward entrypoints

LiveKit audio, video, status, transcript, and transient audio adapters now live under:

```text
avatar-agents/alphaavatar/agents/entrypoints/livekit/
```

This reinforces the intended architecture:

```text
avatar-core
    transport-independent streams, events, timing, lifecycle semantics

avatar-agents / plugins
    reasoning, routing, policies, capabilities, and processors

entrypoints/livekit
    LiveKit RTC and data transport conversion
```

LiveKit remains an RTC transport in v0.6.6, while `livekit.agents` is gradually being removed from AlphaAvatar-owned runtime behavior.

### 5. Transport-independent OutputRuntime

A new output package was added to `avatar-core`:

```text
alphaavatar/core/output/
├── __init__.py
├── runtime.py
├── schema.py
├── stream.py
└── timeline.py
```

`OutputRuntime` provides a shared, time-aligned output plane for:

- semantic status events;
- source text chunks;
- speech requests during compatibility migration;
- normalized audio frames;
- text-audio alignment events;
- transport playout feedback;
- delivered transcript chunks;
- interruption and completion control events.

Core identifiers now have distinct semantics:

```text
turn_id
    groups outputs belonging to one interaction turn

output_id
    identifies one complete logical message or utterance

chunk_id
    identifies one source-text or delivered-transcript segment
```

Multiple outputs may exist in the same turn. A new `output_id` may replace an older active output in the same lane, while later chunks using the same `output_id` append to the same logical output.

Interrupted or completed output IDs cannot be reopened.

### 6. Output lanes and delivery modes

The output runtime defines transport-independent lanes:

- `ASSISTANT`
- `TRANSIENT`
- `STATUS`
- `CHARACTER`

Source text also declares how it should be delivered:

- `MIRROR`: retained for timeline and observability while another system owns delivery;
- `IMMEDIATE`: may be delivered immediately without audio synchronization;
- `AUDIO_SYNCED`: visible text must follow actual audio playout.

During v0.6.6:

```text
Assistant text
    OutputTextMode.MIRROR
    LiveKit AgentSession remains the delivery owner

Transient status message
    OutputTextMode.AUDIO_SYNCED
    AlphaAvatar Router and output adapters own delivery
```

### 7. Priority control and interruption semantics

`OutputControl` is published on the same output timeline as data events.

It currently supports:

- `INTERRUPT`
- `COMPLETE`

Only `INTERRUPT` uses the high-priority control queue. This ensures interruption cannot become trapped behind queued audio frames.

`COMPLETE` remains ordered behind previously produced data, because source production finishing does not mean transport playout has already finished.

On interruption, `OutputRuntime`:

1. marks the logical output terminal;
2. rejects later source chunks and late audio frames for that `output_id`;
3. discards queued raw audio frames;
4. retains source text, alignment, playback, and transcript facts needed for final synchronization;
5. publishes a priority `INTERRUPT` control event to all relevant consumers.

### 8. Status plugin decoupling

The Status plugin no longer owns LiveKit delivery or calls `session.say()`.

Status output is now separated into two concepts:

```text
STATUS
    machine-readable state for UI and character behavior

TRANSIENT message
    optional user-facing text and speech produced by Status policy
```

`RuntimeStatusSink` publishes semantic `STATUS` actions to `OutputRuntime`.

`StatusVoiceOutput` may additionally create an `AUDIO_SYNCED` transient source-text output. It does not know about TTS, LiveKit tracks, or frontend protocols.

A new transient status output replaces the previous transient output even when both belong to the same `turn_id`, because replacement is based on `output_id` and lane rather than turn identity.

### 9. Interaction Router expanded to output routing

The Router now coordinates both input and output processing.

Current input processors include:

- `AudioActivityProcessor`
- `SpeechTranscriptionProcessor`

Current output processors include:

- `SpeechSynthesisProcessor`
- `TranscriptSynchronizationProcessor`

The default conceptual flow is now:

```text
Input:
PerceptionRuntime.audio
    ↓
AudioActivityProcessor
    ↓
PerceptionRuntime.speech
    ↓
SpeechTranscriptionProcessor
    ↓
Transcription events

Output:
AUDIO_SYNCED TEXT_CHUNK
    ↓
SpeechSynthesisProcessor
    ↓
AUDIO_FRAME + ALIGNMENT
    ↓
Transport audio adapter
    ↓
PLAYBACK feedback
    ↓
TranscriptSynchronizationProcessor
    ↓
TRANSCRIPT_CHUNK
```

The Router owns routing and cancellation decisions. Voice plugins own VAD, STT, and TTS capability implementations.

### 10. Transport-independent TTS abstraction

A `TTSBase` capability was introduced for conversion from text into normalized AlphaAvatar `AudioFrame` objects.

A temporary `LiveKitTTSAdapter` wraps existing LiveKit Agents TTS providers during migration.

The adapter does not publish to a transport or mutate `OutputRuntime`; it only converts provider output into AlphaAvatar-owned media frames.

### 11. Stateful speech synthesis

`SpeechSynthesisProcessor` maintains one long-lived synthesis job per `output_id`.

This allows multiple source-text chunks to form one message:

```text
output_id=A, chunk 1
output_id=A, chunk 2
output_id=A, chunk 3
```

Chunks are synthesized in order without interrupting one another.

If output `A` is interrupted:

- the complete synthesis job is cancelled;
- queued source segments for `A` are discarded;
- later chunks using `A` are rejected by `OutputRuntime`;
- late audio frames are rejected.

A new output with a different `output_id` in the same lane replaces the previous output.

### 12. Independent transient audio output

`LiveKitTransientAudioOutput` publishes transient audio on an independent LiveKit audio track.

This avoids the `AgentSession.session.say()` queue behavior that previously caused delayed status speech to play after the final Assistant answer.

The adapter:

- consumes transient `AUDIO_FRAME` events;
- writes frames to a LiveKit `AudioSource`;
- clears queued audio immediately on interruption;
- reports playback start, progress, finish, and interruption;
- tracks pushed, queued, and approximately played audio duration;
- keeps transient speech independent from the final Assistant TTS path.

### 13. Playback-aware transcript synchronization

The new transcript pipeline distinguishes:

```text
generated source text
    what the system intended to say

delivered transcript
    what the user actually heard
```

`SpeechSynthesisProcessor` publishes `ALIGNMENT` events that map each source-text chunk to its generated audio interval.

`LiveKitTransientAudioOutput` publishes `PLAYBACK` feedback.

`TranscriptSynchronizationProcessor` combines source text, text-audio alignment, actual played duration, and interruption controls. It then emits incremental `TRANSCRIPT_CHUNK` events.

When transient audio is interrupted:

- already delivered transcript remains visible;
- unplayed text is never published;
- the final transcript event is marked `interrupted=True`;
- the original generated source text remains available in the output timeline.

Current fallback alignment uses estimated token/character weighting within each synthesized audio interval. The architecture supports replacing this with provider-supplied word timing later.

### 14. LiveKit output adapters

The current LiveKit output layer includes:

- `LiveKitStatusOutput` for machine-readable status actions;
- `LiveKitTransientAudioOutput` for transient audio frames and playout feedback;
- `LiveKitTranscriptOutput` for synchronized transient transcript updates.

`LiveKitStatusOutput` no longer sends user-visible status text or generates transcription. It publishes only status action events.

`LiveKitTranscriptOutput` consumes `TRANSCRIPT_CHUNK` events and updates one LiveKit transcription segment per `output_id`, preserving compatibility with existing frontend behavior.

### 15. Assistant output migration boundary

The final Assistant output is deliberately not migrated in this snapshot.

Current behavior:

```text
Assistant source text
    mirrored into OutputRuntime
    used for timeline visibility and transient preemption

Assistant user-visible text and TTS
    still owned by LiveKit AgentSession
```

This prevents duplicate Assistant messages and avoids expanding the v0.6.6 scope into a complete replacement of the LiveKit Agent output pipeline.

A later release can route Assistant `AUDIO_SYNCED TEXT_CHUNK` events through the same speech synthesis, playback, and transcript path without redesigning `OutputRuntime`.

## User Experience Improvements

The completed work fixes the delayed filler-speech failure mode:

```text
Before:
Assistant answer
    ↓
queued “Okay, let me think.”

Now:
“Okay, let me thi—”
    ↓ interrupted immediately
Assistant answer
```

It also establishes the intended synchronized transcript behavior:

```text
Audio played:
“Okay, let”

Visible transcript:
“Okay, let”

Unplayed source text:
“me think.”
    not shown after interruption
```

Status actions can be consumed independently by the frontend for thinking animations, tool progress, Avatar state, or other UI behavior without treating them as user-visible conversation messages.

## Validation Completed

The current integrated runtime has been manually verified for:

- successful staged plugin startup;
- Router startup with audio activity, STT, TTS, and transcript synchronization processors;
- transient speech playback through the independent LiveKit track;
- status action delivery;
- synchronized transient transcript delivery;
- final Assistant response interrupting active transient speech;
- preservation of already delivered transcript after interruption;
- rejection of unplayed transcript after interruption;
- text and audio output functioning together;
- normal session startup and shutdown.

No dedicated test files were added as part of this work.

## Known Limitations

### Segment-level fallback alignment

The current fallback synchronizer estimates word or character timing from source text, synthesized audio duration, and weighted text units.

This is not true acoustic word alignment. Pauses, emphasis, and language-specific speaking rate can make the estimated boundary differ from the spoken boundary.

Provider-supplied word timing should replace the fallback when available.

### Partial alignment during synthesis cancellation

If a provider synthesis stream is cancelled before a source segment publishes its final alignment, the transcript synchronizer may have insufficient information for the earliest interrupted audio.

A follow-up should publish partial alignment from the synthesis task’s cleanup path whenever any audio was already produced.

### Two LiveKit audio tracks during migration

The Agent participant currently publishes:

- the LiveKit AgentSession Assistant audio track;
- the AlphaAvatar transient audio track.

Some debugging interfaces may display these as two Agent rows even though they belong to one participant.

This remains a transitional limitation until final Assistant TTS is migrated.

### Assistant output is still split across ownership domains

`OutputRuntime` mirrors final Assistant source text, but AgentSession still owns user-visible Assistant text, TTS, interruption, and transcript synchronization.

Full ownership migration is intentionally outside the current v0.6.6 scope.

## Architectural Direction

The v0.6.6 work completed so far establishes the following long-term boundary:

```text
avatar-core
    owns transport-independent perception and output streams,
    timing, lifecycle, interruption, and alignment semantics

Router
    owns input/output routing decisions and processor lifecycle

Voice
    owns VAD, STT, and TTS capability implementations

Status
    owns semantic status policy and optional transient-message decisions

Entrypoints
    own LiveKit and channel transport conversion

AvatarEngine
    owns composition and high-level orchestration
```

This design supports full-duplex, asynchronous, modular operation while allowing LiveKit Agents to be removed incrementally rather than through a disruptive one-step rewrite.
